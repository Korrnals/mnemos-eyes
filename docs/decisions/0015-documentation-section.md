# ADR 0015: Раздел документации (/docs)

- Status: **Принято** (комитет 2026-09-22)
- Deciders: Product Architect, Analytics Lead, Senior System Engineer;
  вёл `@GCW: Tech Lead`
- Related: ADR 0011 (единое web-приложение), ADR 0012 (LAN/offline-рамка),
  спека агентов `docs/design/2026-09-19-agents-section-spec.md` (контент)

## Context

Документация сегодня живёт вне продукта: README и runbook-заметки —
оператор и члены семьи не видят её из интерфейса. Борд — LAN-продукт,
обязанный работать офлайн (включая Tauri), поэтому внешний docs-сайт и
бэкенд-отдача доков не подходят. Материал уже существует — README,
`scripts/backup-all.sh`, `server/security.py`, спеки в `docs/design/` —
его нужно собрать, а не сочинять с нуля.

Две опасности встроенных доков известны заранее. Первая — устаревание: на
самохостед-системе с одним-пятью пользователями устаревшая инструкция по
восстановлению опаснее отсутствующей — её прочитают в аварии и поверят.
Вторая — сырой HTML внутри markdown — классический канал XSS.

## Decision

Раздел «Документация» — чисто фронтендовый домен `/docs` в React-viewer;
бэкенд не меняется — ни эндпоинтов, ни OpenAPI, ни кодогенерации типов.

### 1. Markdown компилируется в бандл UI

Контент — файлы `viewer/src/features/docs/content/{ru,en}/*.md`, попадающие
в бандл через `import.meta.glob` с `query: '?raw'` (compile-time; чанки
ленивые — `eager: true` запрещён). Доки жёстко сшиты с версией приложения:
версия доков = `app_version`, правка страницы = патч-релиз — класс ошибок
«доки не совпадают с развёрнутой версией» исчезает по построению.

### 2. Рендер: react-markdown + remark-gfm, без сырого HTML

Единственная точка рендера — `Markdown.tsx` (react-markdown + remark-gfm,
~30–45 КБ gzip). rehype-raw запрещён: HTML внутри markdown не
интерпретируется. Ссылки получают `rel="noopener noreferrer"`, внутренние
ссылки на `/docs/*` идут через `<Link>`.

### 3. Манифест строится из frontmatter

Каждая страница несёт frontmatter (все поля обязательны):

```yaml
---
title: Развёртывание и первый запуск
slug: deploy                # = имя файла
category: getting-started   # из categories.ts
order: 1                    # внутри категории
last_verified: "1.13.0"     # версия последней проверки
---
```

Манифест (slug, категория, порядок, локали) парсится из frontmatter всех
файлов при инициализации модуля. Файл с битым frontmatter исключается из
навигации с ошибкой в консоли — приложение не падает; integrity-тест (§6)
ловит это до релиза; ручной список страниц и билд-скрипт не нужны.

### 4. Структура: 8 task-based категорий, 12 страниц v1

Навигация — по задачам («как выдать токен», «как восстановить бэкап»), не
по ролям и не по клик-путям: задача переживает рефакторинг UI, клик-путь
«Меню → …» гниёт. Категории: начало работы (развёртывание, первый вход),
панель и группы, агенты и поручения, автоматизация, устройства и
подключение, безопасность и токены (включая ротацию), обслуживание
(бэкап/восстановление, обновление, траблшутинг), частые вопросы. Правила
страницы: одна страница — одна задача; цель — в первом абзаце; клик-путь —
точными ярлыками UI; без скриншотов; секреты в примерах — только масками.

### 5. Локали: RU-первичный корпус

UI=ru → всегда русский (полный корпус v1). UI=en → английская версия, если
есть; иначе русская с видимым бейджем «страница доступна на русском» —
молчаливого фолбэка нет. Незаконченный перевод не публикуется: наполовину
переведённые доки разрушают доверие.

### 6. Пять обязательных гейтов безопасности и качества

1. **ESLint** override для `features/docs`: запрет импортов `rehype-raw`,
   `rehype-sanitize` и `dangerouslySetInnerHTML`.
2. **Hostile-фикстурный тест**: md с `<script>`, `<img onerror>`,
   `javascript:`-ссылкой, `<iframe>` рендерится без script/iframe/onerror;
   href — только http/https/mailto/#.
3. **Integrity-тест**: валидный frontmatter у каждого md (категория
   существует, slug = имени файла, order уникален) + corpus-рендер всех
   страниц без ошибок.
4. **Единственная точка** react-markdown (`Markdown.tsx`); пункт PR-чеклиста:
   «docs: страницы обновлены / без влияния на доки».
5. **Architecture-тест**: в `features/docs` нет импортов `gateway/*` —
   доки статичны и не являются каналом данных.

### 7. Бюджет чанков и поиск

Docs-чанки ленивые (не в entry), суммарно ≤120 КБ gzip; замер размеров из
сборки — в описании каждого PR раздела. Поиск v1 — клиентский, без внешних
сервисов: индекс по активной локали строится при первом открытии `/docs`,
матч префиксный («токен» находит «токена», «tokens»), ранжирование
title > заголовки > текст. Запросы без результатов пишутся в localStorage —
это контентный бэклог авторов, не метрика качества поиска.

## Alternatives rejected

- **Внешний docs-сайт со ссылкой из UI** — LAN-борд обязан работать офлайн;
  доки — часть продукта, а не внешний ресурс.
- **Бэкенд-эндпоинт `/api/docs`** — контрактная цепочка (схема → тесты →
  снапшот → кодогенерация) ради статики + класс рассинхрона «диск vs образ».
- **Оверлей md из тома (правка без пересборки)** — второй источник истины и
  traversal-поверхность; лаг и так закрывается патч-релизом (каденс — часы).
- **EN-only корпус с фолбэком как MVP** — владелец русскоязычен, UI-дефолт
  ru; требование не выполняется с первого дня.
- **Собственный мини-рендер markdown** — ферма багов парсинга и рукописное
  экранирование (XSS); экономия ~30 КБ gzip не окупается.
- **Аудитори-сегментация навигации («для оператора / для семьи»)** —
  task-based структура устойчивее: одна страница закрывает задачу для обеих
  аудиторий.

## Consequences

- В навигации — домен «Документация» (иконка, секции-категории, крошки
  `/docs/*`); снепшоты Shell обновляются — принятая стоимость.
- Маршруты: `/docs` (индекс), `/docs/c/:category`, `/docs/:slug`. В статье:
  анкоры h2/h3, «На этой странице» со scroll-spy, prev/next по манифесту,
  кнопка «копировать» в code-блоках.
- `last_verified` виден читателю; PR с видимым изменением UI обязан
  обновить страницы доков или пометить «без влияния на доки» (гейт 4).
- Морфология русского поиска в v1 закрыта префиксным матчем; стеммер и
  нечёткий поиск — v2 по накопленному zero-result логу.
- Метрики v1 — только честные сигналы: zero-result запросы, поиск→клик,
  сессии с `/docs`; оценки «нравится/не нравится» при 1–2 голосующих — шум.
