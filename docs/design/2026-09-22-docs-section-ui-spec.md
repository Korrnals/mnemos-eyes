> Owner: `@GCW: UI/UX Designer`. Реализация: `@GCW: Senior Frontend Developer` (D3).
> Правило №1: **никаких literal colours** — только токены из `viewer/src/styles/tokens.css`
> через существующие Tailwind-алиасы (`bg-well`, `bg-elevated`, `text-foreground-secondary`,
> `text-iris-bright`, `border-border-subtle`, `shadow-float`, `duration-instant`, …).

## 1. Рамка и принципы

1. Спека детализирует **визуальный слой** контракта и ему не противоречит: модули,
   маршруты, frontmatter, политика локалей, механика поиска — там (§§3–8). Здесь — layout,
   типографика, состояния, адаптивность, тёмная тема.
2. Раздел документации — **спокойная читательская поверхность**. Вся смелость раздела —
   в чистой типографике и точном scroll-spy; iris-акцент работает только на интеракции
   (ссылки, активный пункт TOC, фокус). Декоративного iris-глоу, градиентов и «героев»
   в разделе нет — breathing-ирис остаётся сигнатурным моментом дашборда, а не доков.
3. Доки — contemplative-поверхность: **не потребляют `--row-h`/`--list-gap`**
   (переключатель плотности их не двигает), шаги берутся напрямую из `--space-*`,
   мера чтения — из `--measure-scroll` (72ch), как у «скролла памяти».
4. Шрифт статей — `--font-ui` (Inter), **не** `--font-scroll` (Lora). Решение: Lora в
   продукте зарезервирована за «памятными свитками» (семантическая граница поверхностей);
   доки — операционный справочник с плотным инлайн-кодом, таблицами и ярлыками UI,
   где sans + mono читается точнее. JetBrains Mono (вес 400 — других не загружено,
   см. `fonts.css`) — весь код.
5. Один h1 на страницу; заголовок маршрута в TopBar остаётся `<p>` (конвенция TopBar).
   Иерархия: TopBar → sticky-крошки → шапка раздела → контент.

## 2. Сайдбар-домен «Документация» (NAV_DOMAINS)

Домен встраивается в `NAV_DOMAINS` по образцу домена «Система» (иконка `BookOpen`,
порядок — после «Агенты», перед «Хранилища»):

- домен: `{ to: "/docs", key: "nav.docs", icon: BookOpen }`;
- секции — 8 категорий: `{ to: "/docs/c/<slug>", icon: <lucide из categories.ts> }`;
- i18n: секции сайдбара потребляют **те же ключи** `docs.cat.*`, что и страницы
  категорий — единый источник имён, расхождения невозможны;
- раскрытие секций — по конвенции доменов: только когда pathname в `/docs/*`
  (prefix-active), подсветка активной секции `text-iris-bright font-medium`,
  `aria-current="page"`.

**Требование к навигации (не покрыто базовым `isPathActive`):** на статье
`/docs/<slug>` ни одна секция `/docs/c/<cat>` префиксом не матчится. Активная секция
категории должна подсвечиваться и на странице статьи (slug → category через манифест).
Это поведение, не механика — D3 выбирает способ (передача маппинга в `navItems`
или расширение проверки).

**Чего в сайдбаре нет намеренно:** «На этой странице» (TOC статьи). Сайдбар — доменный
слой (категории), TOC — страничный (правый рельс). Дубль в сайдбаре делал бы третий
уровень навигации, который каркас (two-layer: домен → секция) запрещает.

## 3. Индекс `/docs` — обзор категорий

```
┌──────────────────────────────────────────────────────────────┐
│ TopBar: mnemos-eyes   [ глобальный поиск / ]   RU|EN  ☼  …   │
│ (крошек нет — /docs корневой маршрут раздела)                │
├──────────────────────────────────────────────────────────────┤
│ Документация                                    [ поиск ▾ ]  │  ← h1 + DocsSearch
│ Справочник по бору: от первого запуска до обновления.        │  ← подводка, secondary
│                                                              │
│ ┌────────────┐ ┌────────────┐ ┌────────────┐                 │
│ │ [icon]     │ │ [icon]     │ │ [icon]     │                 │
│ │ Начало     │ │ Панель и   │ │ Агенты и   │   … всего 8     │
│ │ работы     │ │ группы     │ │ поручения  │                 │
│ │ Описание…  │ │ Описание…  │ │ Описание…  │                 │
│ │ 2 страницы │ │ 1 страница │ │ 1 страница │                 │
│ └────────────┘ └────────────┘ └────────────┘                 │
│ ┌────────────┐ ┌────────────┐ …                              │
└──────────────────────────────────────────────────────────────┘
```

- Шапка: `h1` `text-xl font-semibold` (конвенция страниц проекта) + одна строка-подводка
  `text-sm text-foreground-secondary`. Подводку пишет Docs Writer, ключ `docs.index.lede`.
- Справа в строке заголовка — `DocsSearch` (§8), `max-w-xs`, на < md переезжает на
  отдельную строку под заголовком на всю ширину.
- Сетка карточек: `grid grid-cols-1 sm:grid-cols-2 xl:grid-cols-3 gap-4` (3→2→1).
  8 карточек дают ряд 3+3+2 — рваный последний ряд допустим, расталкивать «флексом»
  не нужно.
- Карточка = существующий `Card` (`rounded-md border-border-subtle bg-well shadow-well`
  `p-6`) целиком обёрнут в один `Link`: иконка (`size-5 text-foreground-secondary`),
  название (`text-base font-medium text-foreground`), описание (`text-sm
  text-foreground-secondary`, 2 строки max), число страниц (`text-xs
  text-foreground-muted`, внизу карточки). Число — словами i18n-плюрализацией
  («2 страницы» / «1 страница» / «5 pages»), не голая цифра.
- Обоснование сетки одинаковых карточек (анти-слоп): это навигационный обзор из
  8 **различных** сущностей с собственными иконками/именами/описаниями, а не контентные
  модули-клоны. Второй уровень (категория) карточной сетки уже не использует — см. §4.

Состояния: сводная матрица в §10.

## 4. Категория `/docs/c/:category` — список страниц

Карточную сетку второго уровня не повторяем (паттерн «SaaS-каталог из одинаковых
карточек» — в чёрном списке). Внутри категории — строчный список:

```
┌──────────────────────────────────────────────────────────────┐
│ [иконка категории] Обслуживание                 [ поиск ▾ ]  │  ← h1
│ Бэкап, обновление, диагностика — что делать, когда что-то…   │
│ ──────────────────────────────────────────────────────────── │  ← border-subtle
│ Бэкап и восстановление                            v1.13.0    │  ← строка-ссылка
│ Как снять борд с бэкапа и вернуть его на место.              │
│ ──────────────────────────────────────────────────────────── │
│ Обновление борда                                  v1.13.0    │
│ …                                                            │
└──────────────────────────────────────────────────────────────┘
```

- Строка — блочный `Link` (`min-h` ≥ 56px, паддинги `py-4`): заголовок страницы
  (`text-base font-medium`, hover → `text-iris-bright`), описание (`text-sm
  text-foreground-secondary`), справа — `last_verified` (`text-xs
  text-foreground-muted`, моно-цифры не нужны, версия текстом «v1.13.0»).
- Порядок строк — `order` из frontmatter (контракт §5); в UI порядок не показываем,
  он просто соблюдён.
- Разделители строк `border-b border-border-subtle`, у последней строки — нет.
- Активные состояния строки: hover `bg-elevated` (на всю ширину строки, с
  отрицательным паддингом-компенсацией либо без фона — достаточно смены цвета
  заголовка; фон опционален), focus-visible — стандартное кольцо `outline-iris-bright`.

Пустая категория в v1 невозможна (контракт §5: все 8 категорий непустые), отдельного
empty-состояния у страницы категории нет — за это отвечает integrity-тест манифеста.

## 5. Статья `/docs/:slug`

### 5.1 Каркас (xl и шире)

```
┌───────────────────────────────────────────────────────────────┐
│ TopBar + крошки: Документация › Обслуживание › Обновление…    │
├──────────────────────────────────────────────┬────────────────┤
│ ◇чип «Обслуживание» [v1.13.0] [RU-бейдж] [🔍]│ На этой странице│ ← sticky
│ Обновление борда                        (h1) │ ─────────────── │
│ ── мера статьи: --measure-scroll (72ch) ──── │ ● Установка     │
│ Абзац: 16px / leading-relaxed…               │ ○ Перед обновл. │
│                                              │ ○ Обновление    │
│ ## Перед обновлением                         │ ○ Если что-то…  │
│ Текст с [инлайн-кодом] и ссылкой…            │                 │
│ ┌ code-блок ──────────────────── [копир.] ┐  │   (рельс не     │
│ │ helm upgrade mnemos/…                   │  │    скроллится   │
│ └─────────────────────────────────────────┘  │    со страницей)│
│ …                                            │                 │
│ ┌──────────────────────┬────────────────────┐│                 │
│ │ ← Предыдущая страница│ Следующая страница ││                 │
│ └──────────────────────┴────────────────────┘│                 │
└──────────────────────────────────────────────┴────────────────┘
```

- Сетка: `grid grid-cols-[minmax(0,1fr)_16rem] gap-8`, обе колонки в контейнере
  `max-w-5xl mx-auto`. Колонка статьи — `max-width: var(--measure-scroll)` (72ch),
  при 16px это ~700px — верхняя граница рекомендованной меры чтения.
- Правый рельс TOC — `aside` со `sticky`, `top` = высота TopBar (56px) + строка крошек
  (~41px) + 1 шаг (`--space-4`): итого `top-28` (112px), чтобы рельс выезжал из-под
  sticky-шапки, а не под неё. У самого рельса `max-h` с внутренним скроллом не нужен
  при 12 страницах v1, но задать `max-h-[calc(100dvh-8rem)] overflow-y-auto` — дёшево
  и защищает будущие длинные статьи.
- `scroll-margin-top` всех h2/h3 = `var(--space-24)` (96px) — якорь не прячется под
  sticky-шапкой (это же требование WCAG 2.4.11 к фокусу после перехода по якорю).

### 5.2 Шапка статьи

Порядок визуальных элементов (сверху вниз, к поиску — вправо):

1. Мета-строка: чип категории → бейдж версии → (опц.) бейдж локали; справа `DocsSearch`.
2. `h1` — `text-xl font-semibold leading-tight text-foreground`.
3. Статья.

- **Чип категории** — `Badge` (существующий компонент, вариант `default`:
  `bg-elevated text-foreground-secondary`) — и это `Link` на `/docs/c/<category>`
  (выход «на уровень вверх» без крошек на узких экранах, где крошки усекаются).
- **Метка актуальности** — `Badge` вариант `outline` с текстом «актуально для v1.13.0»
  (`border-border text-foreground-secondary`, иконка не нужна). Источник —
  `last_verified` frontmatter. Это часть контракта видимости версий: читатель видит
  свежесть без раскрытия «О программе».
- Бейдж локали — §9; появляется в этой же мета-строке, после версии.
- Расстояния: мета-строка `mb-3` (`--space-3`), h1 → статья `mt-4` (`--space-4`).

### 5.3 Правый рельс «На этой странице»

- Заголовок рельса: `text-xs font-medium text-foreground-secondary`, текст
  «На этой странице» (`docs.toc.title`), `mb-3`. Без caps-трекинга и прочей типографики
  «eyebrow» — это функциональная подпись.
- Список: h2 — верхний уровень, h3 — отступ `pl-4`. Пункт: `text-sm py-1.5` (высота
  ≥ 24px, WCAG 2.5.8) `text-foreground-secondary`, hover → `text-foreground`;
  `truncate` + `title` с полным текстом для длинных заголовков.
- Активный пункт (scroll-spy, IntersectionObserver по контракту): `text-iris-bright
  font-medium` + `border-l-2 border-iris` на пункте (индикатор формой + цветом —
  не только цветом, WCAG 1.4.1). `aria-current="location"`.
- Каждый пункт — якорная ссылка на `#slug` заголовка; переход плавный только если
  не `prefers-reduced-motion` (токены гасят — см. §13).
- Рельс не показывать, если у статьи меньше двух заголовков h2 (пустой TOC — шум).

### 5.4 Prev/next

- В конце статьи, `mt-12` (`--space-12`), сетка 2 колонки (`grid-cols-2 gap-4`),
  на < sm — стопкой. Если страницы нет (первая/последняя), слот пустой не рисуем —
  оставшаяся ячейка тянется на всю ширину.
- Каждый блок — один `Link` с бордером (`border border-border-subtle rounded-md p-4`),
  внутри: подпись-направление «Предыдущая» / «Следующая» (`text-xs
  text-foreground-muted`, со стрелкой-иконкой `ArrowLeft`/`ArrowRight`), под ней —
  название страницы (`text-sm font-medium`). Hover: `border-border` + `bg-elevated`;
  focus-visible — стандартное кольцо. Высота блока ≥ 44px по построению.

## 6. Типографика статьи: элемент → токены → значение

Маппинг markdown-элементов (единственная точка — `Markdown.tsx`, без literal values):

| Элемент | Токены | Значение / примечание |
| --- | --- | --- |
| `h1` (заголовок страницы, вне md-тела) | `--text-xl` `--leading-tight` `--weight-semibold` | 24px; один на страницу |
| `h2` | `--text-lg` `--weight-semibold` `--color-text-primary`; `mt: --space-10`, `mb: --space-4`; `scroll-margin-top: --space-24` | 20px; якорь GitHub-style (контракт §8) |
| `h3` | `--text-base` `--weight-semibold`; `mt: --space-8`, `mb: --space-3`; `scroll-margin-top: --space-24` | 16px, отличается от h2 весом и отступом, не цветом |
| `h4` | `--text-base` `--weight-medium` | 16px medium; ниже h4 в контенте не спускаться |
| `p` | `--text-base` `--leading-relaxed` `--color-text-primary`; `mb: --space-4` | 16px / 1.7 — ритм чтения |
| `ul` / `ol` | `mb: --space-4`, `padding-inline-start: --space-6`; `li + li: mt: --space-2` | маркеры `--color-text-muted` |
| `a` (ссылка) | `--color-iris-bright`, underline, `underline-offset-2`; hover: underline толще; focus: кольцо `--color-iris-bright` | внешние — `rel="noopener noreferrer"` (контракт), внутренние `/docs/*` — `<Link>` |
| `code` (инлайн) | см. §7.1 | |
| `pre` (блок) | см. §7.2 | |
| `blockquote` | `border-l-2 border-iris-dim`, `pl: --space-4`, `--color-text-secondary` | курсив не включать — в кириллице он хуже читается |
| `table` | обёртка `overflow-x-auto rounded-md border border-border-subtle`; `th`: `--text-sm` `--weight-medium` `--color-text-secondary`, низ `border-border`; `td`: `--text-sm`, низ `border-border-subtle`; ячейки `px: --space-3 py: --space-2` | 3:1 для линий заголовка (WCAG 1.4.11, токен `--color-border` уже поднят) |
| `img` | `max-w-full rounded-md border border-border-subtle` | подписи `figcaption` — `--text-xs` `--color-text-secondary` |
| `hr` | `border-border-subtle`, `my: --space-8` | |
| `mark` (подсветка в поиске) | `bg-iris/15 rounded-sm`, текст `--color-text-primary` | см. §8 |

Правило вложенности: инлайн-элементы не меняют `line-height` строки (вертикальный
метрик `p` не прыгает от кода/ссылок).

## 7. Код: инлайн vs блок

### 7.1 Инлайн-код

- `--font-mono`, `--text-sm` (0.875rem — чуть ниже тела 16px, x-height моно выравнивает),
  фон `--color-bg-elevated`, бордер `--color-border-subtle`, `radius: --radius-sm`,
  `px: --space-1.5`→`--space-2`, `py: 1px`;
- цвет текста `--color-text-primary` (акцентом код не красим — iris зарезервирован
  за ссылками; иначе текст статьи «загорается» точками);
- длинные идентификаторы: `overflow-wrap: anywhere` — инлайн-код переносится, а не
  рвёт вёрстку на узких экранах.

### 7.2 Code-блок

- Поверхность: `--color-bg-elevated` + `border border-border-subtle` +
  `radius: --radius-md`; на `--color-bg-base` страницы блок читается и в тёмной, и в
  светлой теме (проверка — §12).
- Текст: `--font-mono`, `--text-sm`, `--leading-normal`, `--color-text-primary`,
  вес 400 (JetBrains Mono грузится только в 400 — жирный код в спеке запрещён).
- Горизонтальный скролл: `overflow-x-auto`; переносы строк кода **не** включать
  (ломают команды при копировании). Скроллбар — системный, стилизованного кастома нет.
- **Кнопка «копировать»**: ghost icon-кнопка (`Button size="icon"`) в правом верхнем
  углу блока, поверх первой строки (`absolute`), `aria-label="Скопировать код"`.
  Подтверждение: иконка `Copy` → `Check` (смена формы, не цвета) на 2с + sr-only
  `aria-live="polite"` «Код скопирован». Тост не используем — шум ради микро-операции.
  Состояния: default / hover (`bg-elevated`) / focus-visible (кольцо) / copied (`Check`,
  кнопка неактивна, `aria-disabled`).
- Языковая метка (bash/yaml) — `text-[10px]`→`--text-xs text-foreground-muted` в
  верхнем левом углу; опционально, если язык указан в ограде.
- Сам блок — не поверхностная «карточка в карточке»: тени нет (`shadow` отсутствует),
  только бордер.

## 8. Поиск по документации

Поле — компонент `DocsSearch`, живёт в шапке раздела на всех трёх страницах
(индекс, категория, статья); справа от заголовка/мета-строки, `max-w-xs sm:max-w-sm`.

- **Поле**: как глобальный поиск TopBar (визуальная рифма): `h-9 rounded-md border
  border-border-subtle bg-well px-3`, иконка `Search size-4 text-foreground-secondary`,
  placeholder «Поиск по документации» (`docs.search.placeholder`), `role="combobox"`
  + `aria-expanded` + `aria-controls` на input (паттерн ARIA combobox/listbox).
  Своего хоткея в v1 нет (`/` занят глобальным поиском) — kbd-подсказки в поле нет.
- **Выпадающая выдача**: абсолют под полем, `bg-elevated border border-border
  rounded-md shadow-float`, `max-h-[60vh] overflow-y-auto`. Пункт результата (кнопка,
  высота ≥ 44px): иконка `FileText` (muted) → заголовок (`text-sm font-medium`) →
  категория (`text-xs text-foreground-muted`) → сниппет (`text-xs
  text-foreground-secondary`) с `<mark>` (таблица §6) вокруг совпадения.
- **Клавиатура**: `↓/↑` — перемещение (`aria-activedescendant` + `aria-selected`),
  `Enter` — переход, `Esc` — закрыть список и вернуть фокус в поле, `Tab` — закрыть
  список. Активный пункт подсвечивается `bg-elevated` (внутри `bg-elevated`
  дропдауна — `bg-overlay`), форма индикатора — левый рельс `border-l-2 border-iris`,
  не только цвет.
- **Пустой результат** — честный текст: «По запросу «…» ничего не найдено» + подсказка
  «Попробуйте одно слово: «токен» вместо «ротация токенов»» (`text-sm`, secondary).
  Логирование zero-result в `localStorage` (контракт §7) из UI никак не проявляется.
- **Индекс строится лениво** при первом открытии `/docs` (контракт): на практике
  запросы клиентские и мгновенные; отдельного loading-состояния у выдачи нет. Если
  индекс ещё не готов (первый рендер большого корпуса) — поле показывает
  `text-foreground-muted` «Индексируется…» и не открывает пустой дропдаун.
- Совпадение подсвечивается и в сниппете, и в заголовке; подсветка — фон, не
  инверсия, чтобы не мигало при перерисовке списка.
- Выбор результата закрывает дропдаун и сбрасывает черновик запроса; повторное
  открытие поля — с пустым состоянием (не «залипший» прошлый список).

## 9. Локальный фолбэк (UI=en, страница только на русском)

- Место: мета-строка шапки статьи, **после** бейджа версии (порядок: категория →
  версия → локаль). На индексе/категории не появляется — фолбэк касается контента
  страницы, а не раздела.
- Стиль: `Badge` вариант `outline`, иконка `Languages size-3.5`, текст по ключу
  `docs.localeFallback` («Доступно на русском» / «Available in Russian only»).
  Цвета — нейтральные (`border-border text-foreground-secondary`): бейдж сообщает,
  а не предупреждает. Никаких warning-цветов, анимации и тултипов-«караулов».
- Бейдж статичен, не интерактивен (в v1 EN-версии нет — «переключить» не на что).
  Полупереведённые страницы не публикуются (контракт §6), промежуточных состояний
  у бейджа нет.

## 10. Матрица состояний

| Компонент / поверхность | Состояние | Визуал | A11y |
| --- | --- | --- | --- |
| Индекс / категория | Loading (lazy-чанк) | skeleton: для индекса — сетка `Card`-скелетов (по образцу `MemoryCardSkeleton`, 6 шт.), для категории — 3 строки-скелета (`TableRowSkeleton`-образец); shimmer, `aria-hidden` | контейнер `role="status"` + `aria-busy="true"`, лейбл «Загрузка…» (`docs.loading`) |
| Статья | Loading | скелет статьи: строка-чип + заголовок + 6–8 строк текста (ширины 100/95/80%…), моно-блока не имитировать | то же |
| Любая страница /docs | Unknown slug → not-found | `EmptyState variant="not-found"` (готовый компонент): «Такой страницы нет» + CTA-кнопка «Все категории» → `/docs`; крошки остаются | `role="alert"` уже в EmptyState |
| Статья/категория | Ошибка рендера md | `EmptyState variant="error"` + `Button variant="outline"` «Повторить» (reset boundary); message — техническая причина, detail — усечён | `role="alert"` |
| DocsSearch | default / hover / focus | как поле TopBar; focus: бордер `--color-iris-bright` | label через `aria-label` |
| DocsSearch dropdown | open / навигация / zero-result / закрыт | §8 | combobox-паттерн §8 |
| Кнопка копирования | default / hover / focus / copied | §7.2 | aria-label + aria-live |
| TOC-пункт | inactive / hover / active / focus | §5.3 | `aria-current="location"` |
| Prev/next | hover / focus / disabled-отсутствие слота | §5.4 | блок-ссылка, направление подписано текстом, не только стрелкой |
| Карточка категории | hover / focus / active | hover: `shadow-raised` + `border-border`; focus: кольцо; active: `bg-elevated` | вся карточка — одна ссылка, `aria-label` = название |
| Строка категории | hover / focus | §4 | `aria-current="page"` не нужен — это список ссылок |

Скрытых состояний «внезапно пусто» в v1 нет (пустые категории исключены контрактом),
но not-found и error-рендер обязательны — оба граничат с пользовательским вводом
(ссылка/слаг) и контентом (md).

## 11. Адаптивность

Брейкпоинты Tailwind: `sm` 640, `md` 768 (форс icon-only сайдбара), `lg` 1024,
`xl` 1280.

| Диапазон | Статья | Индекс/категория | Поиск |
| --- | --- | --- | --- |
| ≥ xl | две колонки, TOC-рельс sticky | сетка 3 колонки | в шапке, справа |
| lg…xl | две колонки, TOC-рельс уже | сетка 2 колонки | в шапке |
| sm…lg | одна колонка; TOC сворачивается в `<details>` над статьёй | сетка 2 колонки | в шапке, `max-w-none` |
| < sm | одна колонка; TOC в `<details>`; prev/next стопкой | сетка 1 колонка | отдельная строка, вся ширина |

- **TOC на узких экранах**: нативный `<details>` с `<summary>` «На этой странице»
  (`text-sm font-medium`, шеврон `ChevronDown`, поворот при открытии
  `duration-instant`) — семантика и клавиатура из платформы, JS-состояние не нужно.
  Раскрыт по умолчанию быть не должен; scroll-spy в свёрнутом виде не считается
  ошибкой (индикатор не виден — его и нет). Расположение: сразу под мета-строкой,
  до h1 — читатель видит карту страницы до погружения.
- **Code-блоки**: `overflow-x-auto` на всех ширинах; на тач-устройствах скролл
  жестом, кнопка копирования остаётся доступной (не уезжает за край — привязана к
  блоку, не к содержимому). Инлайн-код переносится (`overflow-wrap: anywhere`).
- **Таблицы**: обёртка с горизонтальным скроллом, `border` и `rounded-md` у обёртки,
  не у таблицы.
- **Сетка карточек**: `grid-cols-1 sm:grid-cols-2 xl:grid-cols-3` — 3→2→1.
- Крошки на < lg усекаются по среднему элементу (существующее поведение Breadcrumbs,
  `truncate`); чип категории в шапке статьи остаётся видимым полностью — это дубль
  выхода «на уровень вверх».

## 12. Тёмная тема

Переключение в проекте — атрибут `[data-theme="light"]` на `html`, дефолт тёмный
на `:root` (design-system §9, `theme-provider`). Все новые поверхности обязаны
потреблять только семантические токены — тогда корректность в обеих темах
гарантируется дисциплиной, а не перебором цветов. Точечная проверка при ревью:

| Поверхность | Тёмная | Светлая | Риск |
| --- | --- | --- | --- |
| Code-блок `bg-elevated` на странице `bg-base` | #1a1f2e на #0d0f14 | #eff1f5 на #f5f6f8 | пара различима в обе стороны; бордер `border-subtle` добавляет границу |
| `<mark>` `bg-iris/15` | тинт читаем | на белом тинт бледнее — текст остаётся `text-primary`, contrast пары не зависит от тинта | не красить текст mark в iris (в light fail) |
| `Badge` чипы | `bg-elevated`/`border-border` | те же токены | — |
| TOC active `text-iris-bright` | яркий iris на базе | light: `iris-bright` темнее (#136e79) — токен сам решает | — |
| Скелеты + shimmer | по `skeletons.css` | shimmer виден за счёт полупрозрачности | не хардкодить серый |
| Тени (prev/next hover, дропдаун) | `shadow-raised/float` | непрозрачность половинная (переопределена в tokens.css) | — |
| Инлайн-код `bg-elevated` + `border-subtle` | различим от текста | различим | следить, чтобы фон не совпал с фоном таблиц-заголовков (тоже elevated) — допустимо, это одна «песочница» |

Запрет literal colors делает тёмную/светлую проверку дешёвой: если цвет не через
токен — это находка ревью, а не «поправь в двух темах».

## 13. Движение

| Событие | Токены | Примечание |
| --- | --- | --- |
| Открытие дропдауна поиска | `--duration-fast` + `--ease-out`, opacity 0→1 + translateY 8px→0, одним куском | без стаггера — это рабочий инструмент, не «герой» |
| Подтверждение копирования | смена иконки `--duration-instant` | §7.2 |
| Смена активного пункта TOC | цвет/бордер `--duration-instant` | |
| Раскрытие `<details>` TOC | без анимации высоты (нативный элемент), только шеврон `--duration-instant` | |
| Переход по якорю | `scroll-behavior: smooth` | гасится глобальным reduced-motion-правилом проекта |

`prefers-reduced-motion: reduce` обслуживается токенами (`--duration-*` → 0/80ms),
отдельных media-запросов в спеке нет. Новых ambient-анимаций ноль — бюджеты
design-system §7 (максимум 1 ambient: breathing-ирис дашборда) соблюдены.

## 14. Анти-слоп ревью: чего НЕ делать

Чёрный список конкретно для /docs (сверх общего канона):

1. Никаких декоративных градиентов, «тишины-тинтов» и glow-подсветок вне токенов —
   индекс без «героя», статья без фоновых пятен.
2. Никаких иллюстраций-заглушек (undraw-персонажи, абстрактные blob-SVG) в not-found
   и пустых слотах — только `EmptyState` с приглушённым ирисом, как во всём приложении.
3. Никаких emoji в заголовках статей и категорий (иконки — только lucide по конвенции
   навигации).
4. Никаких паттернов «eyebrow caps + "·" + "→"» в шапках — подпись рельса и
   подписи prev/next — обычный small text, без капса и трекинга.
5. Никаких одинаковых контентных карточек на странице категории — там список-строки.
6. Акцент iris — только интеракция (ссылки, active TOC, focus, подсветка поиска).
   Не красить в iris: версии, чипы категорий, иконки карточек, счётчики страниц.
7. Никаких «умных» дополнений к поиску (Ask-AI, подсказки-предсказания) — v1
   префиксный клиентский поиск по контракту.
8. Никаких скриншотов-хрома в контенте и ужимания статей до «маркетинговых лендингов»
   (контракт §5 и так это запрещает — здесь запрещает и дизайн).
9. Motion — только микрокомментарий к действию (§13); никаких scroll-triggered
   появлений блоков статьи.

## 15. Чек-лист приёмки (для D3)

1. [ ] Все цвета/тени/радиусы/шаги — только через токены; `grep` по `features/docs`
   не находит hex/rgb вне tokens.css.
2. [ ] Статья: мера текста ≤ 72ch (`--measure-scroll`), правый рельс sticky,
   scroll-spy работает и в светлой, и в тёмной теме.
3. [ ] `h2/h3` имеют slug-якоря (GitHub-style), `scroll-margin-top` ≥ 96px — якорь
   не уезжает под sticky-шапку.
4. [ ] TOC-пункт ≥ 24px по высоте, активный пункт отличим формой (бордер), не только
   цветом; при < 2 заголовков h2 рельс не рендерится.
5. [ ] На узких экранах (< lg) TOC превращается в нативный `<details>` над статьёй;
   сетка карточек 3→2→1 подтверждена на 1280/768/375.
6. [ ] Инлайн-код и code-блок — JetBrains Mono 400; блок скроллится по горизонтали,
   кнопка «копировать» меняет иконку Copy→Check и говорит об этом через aria-live.
7. [ ] Поиск: combobox-паттерн (стрелки/Enter/Esc с возвратом фокуса), сниппет с
   подсветкой `<mark>`, zero-result — честный текст + подсказка.
8. [ ] Unknown slug → `EmptyState` not-found с CTA на `/docs`; ошибка рендера md →
   error-вариант с «Повторить»; loading обоих индексов — skeleton с `aria-busy`.
9. [ ] Бейдж «доступно на русском» появляется только при UI=en и отсутствии EN-файла,
   стоит после бейджа версии, нейтрального цвета, без интеракции.
10. [ ] Сайдбар: домен «Документация» с 8 секциями-категориями; секция категории
    подсвечена и на страницах её статей; TOC в сайдбаре не дублируется.
11. [ ] Prev/next соблюдает порядок манифеста; крайние страницы не рисуют пустой слот.
12. [ ] Ни одного паттерна из §14 (проверка ревью по списку) — включая «никакого
    iris вне интеракции» и «никаких emoji в заголовках».
