## 1. Рамка

### 1.1 Принципы

1. Раздел остаётся **спокойной читательской поверхностью**. Три проекта — это больше
   контента, а не больше декора: iris по-прежнему работает только на интеракцию
   (ссылки, активный пункт, фокус), героев и градиентов на обложках нет.
2. Обложка хаба — **титульный лист книги**, а не лендинг: имя проекта, один честный
   абзац, строка статуса, «с чего начать», оглавление категорий. Форма едина для всех
   трёх проектов — различается только содержание.
3. Сайдбар остаётся двухслойным **для доменов приложения**; домен «Документация» —
   единственный санкционированный исключение-случай с третьим уровнем (проект →
   категория), введённым контрактом §4. Исключение локализовано: глубже категории
   навигация не идёт нигде (TOC статьи — правый рельс, не сайдбар).
4. Импортированный корпус читается по тем же правилам, что и свой: та же мера
   72ch, тот же Markdown-маппинг. Разница — **только в мета-слое**: провенанс-бейдж
   и локаль-статус. Голос апстрима виден, хром апстрима — нет (контракт §2: тело
   не трогаем, апстрим-хром вырезан синком).

## 2. URL-пространство и маршруты

Контракт §4: слаг страницы = относительный путь с префиксом проекта
(`mnemos/user/getting-started`). UX-следствия фиксируются так:

| URL | Что там |
| --- | --- |
| `/docs` | редирект (replace) → `/docs/vesmaro-eyes` |
| `/docs/vesmaro-eyes` | обложка хаба vesmaro-eyes (9 категорий); **корень раздела** |
| `/docs/vesmaro-eyes/c/:category` | страница категории (как сейчас `/docs/c/:category`) |
| `/docs/vesmaro-eyes/:slug` | статья (существующие 15 страниц, односкладовые) |
| `/docs/mnemos` | обложка хаба mnemos (~16 страниц) |
| `/docs/mnemos/c/:category` | категории `user` / `admin` / `architecture` |
| `/docs/mnemos/*` | статья, многосегментный слаг (`user/getting-started`) |
| `/docs/mnemos-mesh`, `…/c/:category`, `…/*` | то же для mesh (4 страницы) |
| старые `/docs/<slug>`, `/docs/c/<cat>` | редирект-карта → `/docs/vesmaro-eyes/…` (§8) |

- Имя проекта — первый сегмент, брендовое, не переводится: `vesmaro-eyes`,
  `mnemos`, `mnemos-mesh`. Заголовок обложки mnemos — «Mnemos» (регистр по
  написанию проекта), slug остаётся строчным.
- Механика сплата/параметра и защита «первый сегмент — не проект» — решение W1c;
  UX-требование одно: нераспознанный первый сегмент обрабатывается редирект-картой,
  её промах — not-found (§8).
- Категорийные имена mnemos — рекомендация для W1c/писаря: «Пользователю»
  (`user`), «Администратору» (`admin`), «Архитектура» (`architecture`); mesh:
  «Пользователю», «Администратору». Ключи по образцу `docs.projCat.<project>.<cat>`.

## 3. Сайдбар: домен → три проекта → категории

### 3.1 Структура

Домен «Документация» (`BookOpen`, место в порядке не меняется) получает
`linkTo: "/docs/vesmaro-eyes"` — по образцу `/agents` и `/system`. Внутри домена
вместо плоского списка секций — **три группы-проекта**, у каждой — категории:

```
▼ ◆ Документация                      ← домен (активен: pathname ⊂ /docs)
    ▣ vesmaro-eyes                    ← группа проекта (раскрыта — активный проект)
    │   Начало работы                 ← категории: текст, без иконок, глубже
    │   Панель и группы
    │   … (всего 9)
    ▷ ◈ Mnemos                        ← свёрнутая группа: только заголовок-ссылка
    ▷ ◈ mnemos-mesh
```

- **Группа проекта** — ссылка на обложку хаба: иконка `size-3.5`, метка `text-sm`,
  метрики строки секции (`px-2 py-1.5`, `min-h` ≥ 24px, WCAG 2.5.8). Метка —
  имя проекта (бренд, i18n не требует).
- **Категория внутри группы** — текстовая строка без иконки, `text-sm`, отступ
  глубже группы (`pl` + 2 шага), наследует бордер-рельс группы. Без иконок:
  14 иконок подряд — иконный зоопарк; иерархия читается отступом, а не глифом.
- Имена категорий потребляют **те же ключи**, что и страницы категорий
  (`docs.projCat.*` / существующие `docs.cat.*`) — правило единого источника
  прежней спеки §2 сохраняется.

### 3.2 Раскрытие и активность (всё из pathname, без JS-состояния)

- Раскрыта **ровно одна группа** — проект, чей префикс у pathname (`/docs/mnemos/…`
  → группа mnemos). Обложка хаба раскрывает свою группу тоже. Остальные группы
  свёрнуты до заголовка. Это держает потолок списка на уровне нынешнего
  (9 строк + 2 заголовка + домен ≈ 12 строк) — «визуального взрыва» нет даже
  при 14 категориях суммарно.
- Активность:
  - обложка хаба (`/docs/<project>`) → строка группы: `text-iris-bright font-medium`
    + `aria-current="page"` (это текущая страница);
  - статья/категория проекта → строка группы: `text-foreground font-medium`
    (родитель подсвечен, но не «текущий»); строка категории: `text-iris-bright
    font-medium` + `aria-current="page"`.
  - Механика `isDocsSectionActive` расширяется: slug → (project, category) через
    манифест — тот же приём, что в проде для slug → category.
- **Icon-rail** (свёрнутый сайдбар / < md): группы остаются как три иконочные
  строки (иконка + `aria-label` с именем проекта), категории скрываются — глубже
  двух иконных колонок rail не тянет (гигиена UI-19).

### 3.3 Чего в сайдбаре по-прежнему нет

Списков страниц (только категории), TOC (правый рельс), поискового поля,
счётчиков страниц. Групповые заголовки — не аккордеонные кнопки: клик ведёт на
хаб, раскрытие — следствие навигации. Это честнее (ссылка ведёт туда, куда
говорит) и не добавляет четвёртого интерактивного состояния.

## 4. Обложка хаба `/docs/:project`

### 4.1 Композиция

Одна форма для трёх проектов; одна колонка в контейнере `max-w-5xl`; поиск
`DocsSearch` справа от заголовка (как на нынешнем индексе). Никаких карточек,
никакого героя, никакого фон-панеля: разделитель — тонкие линии и воздух.

```
┌──────────────────────────────────────────────────────────────────┐
│ TopBar. Крошек нет — хаб vesmaro-eyes = корень раздела (§5)      │
├──────────────────────────────────────────────────────────────────┤
│ [Brain] Mnemos                                      [ поиск ▾ ]  │ ← h1 + поиск
│ Сервер памяти для ИИ-агентов: хранит контекст, находит его по    │ ← интро, 1 абзац
│ смыслу и возвращает. Здесь — руководство пользователя и админист­ │   text-sm secondary
│ ратора и обзорная архитектура.                                   │
│                                                                  │
│ [Доступно на русском и английском] [из mnemos@abc1234 · синхр.   │ ← статус-строка
│ 23.09]                                                           │   Badge outline
│                                                                  │
│ С чего начать                                                    │ ← text-xs secondary
│ Установка · Первый запрос · Частые вопросы                       │ ← текстовые ссылки
│ ──────────────────────────────────────────────────────────────── │ ← border-subtle
│ Категории                                                        │ ← text-xs secondary
│ ──────────────────────────────────────────────────────────────── │
│ [icon] Пользователю                                   10 страниц │ ← строка-ссылка
│        Контекст, поиск, теги — повседневная работа с памятью.    │
│ ──────────────────────────────────────────────────────────────── │
│ [icon] Администратору                                   5 страниц│
│ …                                                                │
└──────────────────────────────────────────────────────────────────┘
```

Блоки сверху вниз:

1. **Заголовок**: иконка проекта (`size-6 text-foreground-secondary`, слева от
   `h1` на одной строке) + `h1` `text-xl font-semibold` (конвенция страниц).
   Справа — `DocsSearch` (`max-w-xs`, на < md — на отдельную строку).
2. **Интро** — ровно один абзац `text-sm text-foreground-secondary`, мера ≤ 60ch.
   Пишет Docs Writer (L3-слой контракта), ключи `docs.hub.<project>.lede`.
   Один абзац — потолок: обложка, разросшаяся в манифест, перестаёт быть обложкой.
3. **Статус-строка** — бейджи `Badge variant="outline"` в одной строке с
   `flex-wrap`, `gap-2`:
   - *покрытие локалей* — честно, из манифеста: все страницы обе локали →
     «Доступно на русском и английском»; одна локаль → «Доступно на русском» /
     «Доступно на английском»; смесь → «Частично переведено (ru+en)».
     Ключи `docs.hub.coverage.*`. Нейтральные цвета, иконка `Languages size-3.5`;
   - *провенанс* — только у импортных проектов: «из mnemos@abc1234 · синхр. 23.09»
     (микрокопия и стиль — §6). У vesmaro-eyes этого бейджа нет — свои документы
     провенанса не носят.
4. **«С чего начать»** — подпись `text-xs font-medium text-foreground-secondary`
   (стиль подписи TOC — без капса и трекинга), под ней **одна переносимая строка
   текстовых ссылок** на 2–3 страницы (стиль ссылок §6 прежней спеки: iris,
   underline). Список кураторский (L3-конфиг), названия берутся из манифеста
   (не дублируются в словаре). Разделитель между ссылками — « · » как пунктуация
   строки, не как декоративный паттерн (eyebrow+«·»+«→»-сборка отсутствует).
5. **«Категории»** — та же подпись, затем строки-категории: иконка категории
   (`size-5 text-foreground-secondary`), имя (`text-base font-medium`, hover →
   `text-iris-bright`), описание в одну строку (`text-sm secondary`, `truncate`),
   справа счётчик страниц словами (переиспользование `pagesLabel`). Разделители
   `border-b border-border-subtle`, у последней нет. Строка целиком — `Link`,
   метрики как у строк категории (`min-h` ≥ 56px, `py-4`).

### 4.2 Самокритика формы (записано, чтобы не откатили)

- Сетка одинаковых карточек из прежнего индекса **сознательно снята**: под интро
  и статус-строкой она превращает обложку в «SaaS-каталог модулей» и ломает
  единообразие с mnemos/mesh. Строки-категории повторяют язык страниц категорий —
  раздел читается как одна книга, а не три лендинга.
- Тест «убери бренд — останется шаблон?» форма проходит за счёт статус-строки:
  честное покрытие локалей + провенанс в лендинг-шаблонах не встречается, и это
  функциональные элементы, а не декор.
- «Смелость в одном месте» — её здесь нет намеренно: сигнатура раздела —
  точная типографика и навигация; единственный запоминающийся слой обложки —
  честная статус-строка.

### 4.3 Состояния обложки

| Состояние | Визуал | A11y |
| --- | --- | --- |
| Loading (манифест не гидрирован) | скелет: строка-заголовок + 3 строки-скелета категорий (образец `RowsSkeleton`), shimmer, `aria-hidden` | `role="status"` + `aria-busy="true"`, лейбл `docs.loading` |
| Неизвестный проект | редирект-карта → промах → not-found (§8) | `role="alert"` в EmptyState |
| Пустой список категорий | невозможен — integrity-гейт манифеста (контракт §6.6) | — |
| Интро/«с чего начать» не заполнены (L3 ещё не написан) | блок не рендерится (честное отсутствие), обложка не ломается | — |

## 5. Breadcrumbs: четыре уровня

### 5.1 Состав

- Статья импортного проекта: **Документация → Mnemos → Пользователю → Заголовок**
  (первая — ссылка на `/docs/vesmaro-eyes` как вход раздела, вторая — на обложку,
  третья — на категорию, последняя — текст с `aria-current="page"`).
- Статья vesmaro-eyes: **Документация → Категория → Заголовок** — без изменений
  к прежней спеке: дефолт-проект элиминируется, иначе пара «Документация →
  vesmaro-eyes» вела бы на один и тот же адрес.
- Категория импортного проекта: Документация → Проект → Категория.
- Обложки: у `/docs/vesmaro-eyes` крошек нет (корень раздела — конвенция §3
  прежней спеки); у `/docs/mnemos` и `/docs/mnemos-mesh` — Документация → Проект.

Компонент `Breadcrumbs` массив крошек любой длины уже рендерит; изменений
состава — только в `docsCrumbsFor` (разбор двух- и трёхсегментных pathname через
манифест). Заголовок TopBar (`routeTitle`) продолжает брать последнюю крошку —
четырёхуровневость на него не влияет.

### 5.2 Узкие экраны

Нынешний `truncate` на каждом пункте при четырёх уровнях может срезать **название
страницы** — худший возможный результат. Правила приоритетов:

- последний крош — `shrink-0`, никогда не обрезается;
- средние крошы (Проект, Категория) — `truncate` + `title` с полным именем;
- < sm: первая кроша «Документация» схлопывается в иконку `BookOpen` (ссылка
  сохраняется, `aria-label` остаётся; глиф домена читается без подписи, потому
  что домен активен в сайдбаре).
- `flex-wrap` не включать: перенос крошек на вторую строку двигает sticky-рельс
  статьи (его `top-28` рассчитан на одну строку крошек, §5.1 прежней спеки).

## 6. Провенанс-бейдж на импортированной странице

### 6.1 Место и состав мета-строки статьи

Порядок прежний, с одним добавлением: **чип категории → бейдж версии →
провенанс-бейдж → локаль-бейдж**, поиск справа. `flex-wrap` уже есть — на узких
экранах строка переносится без ломки.

```
[Обслуживание] [актуально для v1.13.0] [из mnemos@abc1234 · синхр. 23.09] [На языке оригинала (английский)]
```

### 6.2 Стиль

- `Badge variant="outline"` — те же нейтральные токены, что у бейджа версии
  (`border-border text-foreground-secondary`); иконка `GitCommitHorizontal
  size-3.5` (muted, `aria-hidden`). **Не** warning/error-цвет: провенанс —
  паспорт, а не тревога; дрейф виден по дате без крика (контракт §7).
- Текст: `docs.provenance.badge`: ru «из {{repo}}@{{sha}} · синхр. {{date}}» /
  en "from {{repo}}@{{sha}} · synced {{date}}". Дата — короткая `dd.mm`; SHA —
  короткий (7 знаков).
- Бейдж **статичен** (ссылка на апстрим-репозиторий не гарантирована — клоны
  локальные); `title` несёт полную форму: «Импортировано из репозитория {{repo}},
  коммит {{fullSha}}, синхронизировано {{dd.mm.yyyy}}». `aria-label` с той же
  полной фразой — текст бейджа и так самодостаточен для SR, label добавляет дату
  полностью.
- На своих страницах бейджа нет; на обложке — проектная сводка (§4.1.3);
  на страницах категорий провенанса нет (строки несут только версию).
- Требование к W1a/W1c (гейт, не опция): провенанс приходит **из frontmatter**
  импортированного файла (`upstream_repo`, `upstream_path`, `upstream_sha`,
  `synced_at`) — маркер GENERATED никогда не протекает в отрисованный текст
  статьи. Отсутствие полей у страницы из `content/upstream/` — fail integrity-гейта
  (расширение контракта §6.5 на фронтмонтр).

## 7. Язык: состояние страницы, фолбэк, поиск

### 7.1 Язык страницы — часть состояния

Эффективная локаль страницы = UI-локаль, если страница в ней опубликована, иначе
**язык оригинала** (фронтмонтр `original_locale`; у апстрима mnemos это ru, у
mesh — en, у своих — ru). Это уточняет `localeForPage` прежнего манифеста
(фолбэк «всегда ru» обобщается). Смешение языков на странице по-прежнему
невозможно: страница показывается целиком на одной локали (контракт §5).

### 7.2 Переключение языка

- **Обе локали есть** (mnemos, mesh после W3): глобальный переключатель RU|EN
  меняет контент — работает существующий remount по ключу `slug:lang`; h1, TOC,
  prev/next, крошки пересобираются из манифеста новой локали. Никаких
  дополнительных контролов на странице не нужно — переключатель интерфейса и
  есть переключатель контента (это и есть «язык — часть состояния»).
- **Локаль одна** (mesh до W3 — EN; свои — RU до волны 2): контент остаётся на
  языке оригинала, в мета-строке — бейдж «на языке оригинала ({{название
  языка}})»: ru-интерфейс на EN-странице → «На языке оригинала (английский)»;
  en-интерфейс на RU-странице → "In the original language (Russian)". Ключ
  `docs.localeOriginal` — обобщение `docs.localeFallback` (имя ключа меняет W1c,
  поведение — эта спека). Визуал прежний: `Badge outline`, `Languages size-3.5`,
  нейтральные цвета, статичен. В любую сторону — без warning-окраски.
- Скролл-позиция при смене языка сбрасывается вверх (remount это делает сам) —
  честно: читатель получил другой текст.

### 7.3 Поиск

- Индекс строится по **активной локали** — решения не меняет (контракт §4);
  результаты всегда на языке, который читатель увидит после клика. Смешанных
  выдач нет, пометок «результат на другом языке» не нужно.
- Следствие: EN-only страницы (mesh до W3) не находятся из RU-интерфейса. Это
  не прятать, а назвать: когда в корпусе есть страницы, не покрытые активной
  локалью, блок zero-result получает вторую строку-подсказку `text-sm
  text-foreground-secondary`: «Часть страниц доступна только на английском —
  переключите язык интерфейса (RU|EN в шапке)» (ключ `docs.search.localeHint`,
  en-зеркало симметрично). Условие показа — из манифеста (`∃ page: lang ∉
  locales`), не захардкожено.
- Размер корпуса (~35 стр/локаль) существующий клиент тянет без изменений;
  сидкар-манифест (W1a) остаётся невидимым для UX.

## 8. Редиректы старых URL и not-found

- **Карта**: статический файл «старый путь → новый» (все 15 односкладовых страниц
  + 9 категорийных `/docs/c/<cat>` + сам `/docs`). Покрывается редирект
  старых закладок и внутренних ссылок борда (контракт §4).
- **UX редиректа — невидимость**:
  - навигация `replace` (не `push`): кнопка Back прыгает старый URL;
  - без промежуточного рендера: ни скелета, ни мигания — resolve карты
    синхронен (статический импорт), `Navigate replace` сразу;
  - новый URL появляется в адресной строке — читатель видит, где находится
    (крошки и сайдбар это подтверждают); тостов и баннеров «вы перенесены»
    **нет** — редирект не событие, а свойство ссылки.
- **Промах карты** (ссылка на удалённую/несуществующую страницу): not-found
  без редиректа — `EmptyState variant="not-found"`: заголовок «Такой страницы
  нет», сообщение прежнее, CTA переименован в **«Открыть документацию»** →
  `/docs/vesmaro-eyes` (ключ `docs.notFound.cta` обновляется; «Все категории»
  больше не адресуется — категорийный корень переехал в проекты). Крошки на
  not-found остаются (прежнее поведение). Поисковое поле на not-found не
  добавляем: восстановление через CTA и сайдбар достаточно, а не-found — не
  место для второго поискового инстанса.

## 9. Типографика и поведение апстрим-статей

Импортные страницы длиннее и суше (справочники, широкие таблицы, длинные
команды). Правила — надстройка над §6–§7 прежней спеки, без её ломки:

1. **Мера строки** остаётся `--measure-scroll` (72ch) для всего тела, включая
   импортные. Ничего «пошире для таблиц»: широкая таблица скроллится внутри
   своей обёртки `overflow-x-auto` (§6 таблица, §11 прежней спеки), колонка не
   расширяется — иначе мера чтения плывёт от страницы к странице.
2. **Заголовки h4–h6**: h4 — как в прежней спеке (`--text-base --weight-medium`);
   h5 и h6 — общий облик `--text-sm --weight-medium text-primary` (порядок
   сохранён, спуск ниже h6 в корпус не допускается — integrity-гейт контента).
   В TOC по-прежнему только h2/h3: длинный справочник не должен рождать
   простыню рельса; h4+ остаются типографикой тела.
3. **Длинные код-блоки**: горизонтальный скролл (`overflow-x-auto`, переносы
   выключены), кнопка копирования привязана к блоку, а не к содержимому —
   не уезжает за край (§11 прежней спеки). Высота блока не режется: сворачивать
   длинные листинги в v1 не будем — свёрнутый код в справочнике ловушка.
4. **Sticky-рельс и скролл таблиц**: горизонтальный скролл живёт внутри
   табличной обёртки, страницу не двигает — sticky `top-28` рельса не смещается.
   `scroll-margin-top` (≥ 96px) действует на все якорные заголовки включая
   импортные (§5.1 прежней спеки, WCAG 2.4.11 после перехода по якорю).
5. **Слаги якорей апстрима**: дубли и не-ASCII заголовки апстрима нормализует
   `headingSlug`; коллизии — гейт синка (контракт §6.2), UI-обходы не вводим.
6. **Изображения апстрима**: вендоренные (`assets/upstream/…`), стиль общий с §6
   (`max-w-full rounded-md border-border-subtle`); правило двухтемности касается
   только кураторских схем — SVG апстрима рендерится как есть.
7. **Prev/next внутри проекта**: границы манифеста-проекта — конец чтения.
   Последняя страница проекта не рисует пустой слот «следующей» (прежнее
   правило §5.4), переход «в другой проект» через prev/next запрещён —
   межпроектные переходы живут в сайдбаре и на обложках.

## 10. Адаптивность

| Диапазон | Обложка | Сайдбар | Статья импортного проекта |
| --- | --- | --- | --- |
| ≥ xl | одна колонка, поиск справа | группы+категории, раскрыт активный проект | две колонки, TOC-рельс |
| lg…xl | то же | то же | две колонки, рельс уже |
| sm…lg | поиск `max-w-none` | то же | одна колонка, TOC в `<details>`; широкие таблицы скроллятся в обёртке |
| < sm | поиск отдельной строкой; статус-строка бейджей переносится (`flex-wrap`); «с чего начать» — переносимая строка ссылок | icon-only: три иконки проектов, категории скрыты | то же; крошы: первая — иконка, последняя — без обрезки |

Обложка по построению односкладовая — отдельных перестроек не требует; все
элементы уже стековые строки. Проверочные ширины: 1280 / 768 / 375.

## 11. Тёмная тема

Новых поверхностей с собственным фоном нет — обложка, группы сайдбара и бейджи
собраны из существующих токенов, поэтому дисциплина §12 прежней спеки покрывает
их автоматически. Точечный контроль при ревью:

| Поверхность | Проверка |
| --- | --- |
| Статус-бейджи обложки (`outline` на `bg-base`) | пара `border-border`/`text-secondary` читается в обеих темах; `border` поднят до ≥3:1 (T7) — ничего добавлять не нужно |
| Провенанс-бейдж | текст `secondary` на `bg-base`; иконка muted — декоративная, `aria-hidden`; контраст несёт текст, не иконка |
| Группа сайдбара (активный проект `text-foreground`) vs категория (`text-secondary`) | различие весом и отступом, не только цветом; активная строка — iris + font-medium, как у секций сейчас |
| Разделители обложки `border-subtle` | decorative-only — совпадение с фоном допустимо и задумано |
| Скелет обложки | shimmer по `skeletons.css`, без хардкода серого |

## 12. Движение

Ничего нового. Новые поверхности статичны: раскрытие группы сайдбара —
мгновенная перестановка списка (переходы цвета `duration-instant`, как у секций
сейчас), обложка появляется как обычная страница, редирект без анимации,
бейджи без входов. Motion-бюджет design-system §7 не расходуется; единственная
ambient-анимация проекта по-прежнему breathing-ирис дашборда.
`prefers-reduced-motion` обслуживается токенами, отдельных правил нет.

## 14. Анти-слоп ревью (дельта к §14 прежней спеки)

10. Никаких карточных сеток на обложках — три обложки строятся строками (§4.2).
11. Никаких «героев» проекта: баннеров, градиентных шапок, больших иконок-иллюстраций.

12. Никаких прогресс-баров «покрытие перевода» и процентных виджетов — только
    честный текстовый бейдж.
13. Никаких warning-окрасок у провенанса и локаль-бейджа (паспорт, не тревога).
14. Никаких тултипов-«караулов» на бейджах — `title` с фактами, без оценочных
    формулировок.
15. Никаких межпроектных prev/next и «рекомендованных» блоков-каруселей на статьях.
