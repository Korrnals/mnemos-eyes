## 2. Механизм: параметр `return` (контекстная ссылка), browser back не трогаем

**Выбрано: `?return=` на ссылках детальных страниц + детерминированный
фолбэк.** Каждая list→detail ссылка (таблица §1) добавляет
`return=<encodeURIComponent(pathname + search)>` источника. Детальная
страница читает `return` и делает его целью back-ручки (§3).

### 2.1 Почему `return`, а не альтернативы

| Вариант | Вердикт | Причина |
| --- | --- | --- |
| **(a) `return`-параметр** | **принят** | контекст едет **в самой ссылке**: переживает новую вкладку (middle-click сохраняет возврат — sessionStorage не сохранил бы), шарится, не является скрытым состоянием, пишется один раз при рендере ссылки (freeze-безопасен по построению: ни эффектов, ни подписок), тривиально тестируется как URL |
| (b) sessionStorage «последний список домена» | отклонён | отвечает на неверный вопрос: источник возврата не всегда список **того же домена** (пары 5, 6, 7, 11, 12 — дрилл тегов и агенты ведут в задачи; вкладка памяти — в запись). Доменная память выразила бы только «корень своего раздела», т.е. воспроизвела бы нынешнюю боль. Плюс скрытость, мульти-таб семантика и отдельный код записи/чистки |
| (c) back-ручка = `history.back()` с фолбэком | отклонён как первичное поведение | непредсказуемый адресат: после detail→detail (пара 12) или смены вкладки `back()` уводит не в список; при прямом открытии — пустой no-op, требующий всё равно фолбэка. Нет `href` → хуже для клавиатуры/SR и middle-click. NN/g: предсказуемость важна умности. Browser back **и так работает** (URL-first + ScrollRestoration) — дублировать его кнопкой незачем |

### 2.2 Правила (контракт для FE, без кода)

1. **Сборка**: `return` = текущие `pathname + search` источника, закодированные
   `encodeURIComponent` целиком, один раз. Никакой ручной конкатенации
   (двойное кодирование `:` в `project:gcw` — только через кодирование целого).
2. **Чтение/валидация** на детальной странице: декодировать; принять, только
   если путь начинается с одного `/` (не `//`, нет схемы — anti-open-redirect),
   принадлежит маршрутам приложения и **не совпадает** с текущими
   pathname+search (запрет самовозврата). Иначе — молча фолбэк (§3), никогда
   не ошибка.
3. **Вложенность**: каждая ссылка хранит только **своего** непосредственного
   предка → цепочки detail→detail (пара 12) разрешаются рекурсивно и честно:
   запись → задача (с её собственным `return` на список) → список.
4. **Вкладки задачи** (`?tab=`): переключение вкладки сохраняет `return`
   (наследует остальные параметры) — иначе первый же клик по вкладке убивал бы
   контекст.
5. **Что не пишет и не читает `return`**: SSE/`taskEvents` (кэш-патчи не
   трогают URL), refetch, мутации. Параметр инертен — freeze-gate 1.11.4
   остаётся зелёным по построению.
6. **Канонический URL** задачи/записи — без `return`; параметр — транспортный
   контекст перехода, не идентификатор. Фолбэк при его отсутствии обязан
   давать тот же результат, что сегодня.
7. **Протухший источник** (тег удалён, запись исчезла из фильтра): страница
   возврата рендерит свои честные empty-состояния (они есть, UI-17 §6) —
   отдельной обработки нет.

### 2.3 Анти-кейсы

| Кейс | Поведение |
| --- | --- |
| Direct-open / закладка / вставленная ссылка без `return` | фолбэк: back-ручка ведёт на корневой список домена (как сегодняшние `BackLink`); крошки дают ориентацию |
| Новая вкладка из detail-ссылки | `return` в URL → контекст сохранён (превосходство над (b)) |
| История другой сессии/внешний реферер | не участвует: механика не читает history вообще |
| Нажатие browser back | работает как сегодня: POP + ScrollRestoration (включая скролл) — единственный путь с гарантированным скроллом (§3, ограничение) |
| Циклический `return` на себя | снят правилом 2 (запрет совпадения с текущим адресом) |

## 3. Back-affordance

### 3.1 Размещение и вид

Один контрол во **всех** детальных страницах — ведущий элемент липкой
крошечной строки (`Shell.tsx`, строка существует на всех level 2–3),
слева от trails. Никаких отдельных in-page BackLink: нынешние «← Все записи» /
«← Все сессии» удаляются, `/tasks/:id` получает ручку впервые. Один паттерн
вместо трёх поведения.

```
┌ TopBar: Задача ──────────────────────────────────────────────────┐
│ ‹ Список   Задачи › T-128 memory-edges          (sticky bar)     │
└───────────────────────────────────────────────────────────────────┘
  ↑ back-контроль        ↑ trails (ориентация: домен › сущность)
```

- **Вид**: `ArrowLeft` (lucide, `size-4`) + короткое имя источника
  («Список», «Канбан», «Теги», «Архив», «Поиск»…); текст скрывается на узких
  экранах (иконка ≥24×24, WCAG 2.5.8). Стиль — существующий ghost-паттерн
  (`TagDrillView` «← Все теги»: `min-h-6`, focus ring `outline-iris-bright`
  2px/offset 2, hover `text-foreground`). Новых цветов/шрифтов ноль.
- **Поведение**: это `Link` (не кнопка): адрес = валидный `return`, иначе
  фолбэк `/tasks` · `/memory` · `/system/sessions` соответственно. Имя
  источника для подписи — `routeTitle(returnPathname)` (существующая функция,
  новые словари имён не нужны).
- **Trails детальных страниц сокращаются до «домен › сущность»**: средняя
  крошка-секция («Список»/«Записи»/«Сессии») удаляется — её роль прецизного
  возврата перешла контролю, а несоответствие «Список→/tasks» исчезает
  удалением, а не третьей правкой. Ориентация «домен › сущность» остаётся.

### 3.2 State-матрица контрола

| Состояние | Условие | Вид |
| --- | --- | --- |
| default | есть валидный `return` или фолбэк | ghost-ссылка `‹ {источник}` |
| hover | указатель | `text-foreground` (существующий transition-colors instant) |
| focus-visible | клавиатура | outline 2px `iris-bright`, offset 2, не перекрывается (полоса sticky, но контрол в её потоке — 2.4.11 соблюдён) |
| active | нажатие | без смещения/анимации (только цвет) |
| disabled | — | не существует: контрол рендерится всегда |
| error/invalid `return` | правило 2 §2.2 провалилось | молча фолбэк — ошибки как состояния нет |
| loading/empty | — | не применимы (статическая навигация) |

### 3.3 A11y

- Семантика: `Link` с `href` — естественный Tab-порядок (контроль первый в
  строке, совпадает с визуальным порядком, WCAG 2.4.3), middle-click/открыть
  в новой вкладке работают как у любой ссылки.
- Доступное имя — с адресатом, не голое «Назад»: `aria-label="Назад: {место}"`
  (WCAG 2.4.4/2.5.3 — имя из видимого текста + адресат). Фокус на `<main>`
  при переходе уже делает `FocusMain` (Shell).
- Цель ≥24×24 (2.5.8): `min-h-6` + иконка — уже паттерн проекта.
- Информация не кодируется цветом: стрелка + текст/aria.

### 3.4 Микрокопии (готовые строки; `ru.ts`/`en.ts`)

| Ключ | RU | EN |
| --- | --- | --- |
| `nav.backTo` | `Назад: {{place}}` | `Back: {{place}}` |
| `nav.backFallback` | `Назад` | `Back` |

Имена мест (`place`) — существующие ключи: `nav.taskList` «Список»,
`nav.taskBoard` «Канбан», `nav.tags` «Теги», `nav.taskArchive` «Архив»,
`nav.taskInbox` «Входящие», `nav.records` «Записи», `nav.search` «Поиск»,
`nav.pulse` «Пульс», `nav.agentsExecution` «Исполнение»,
`nav.systemAutomation` «Автоматизация», `nav.sessions` «Сессии».

Ограничение (честно): переход по контролю — PUSH, поэтому `ScrollRestoration`
(работающий только на POP) скролл не вернёт — список откроется сверху, но с
полными фильтрами и мгновенно (кэш React Query). Гарантированный
скролл-возврат — browser back. Это осознанный размен против непредсказуемого
`history.back()` (§2.1c).

## 4. Критерии приёмки

Общие (все пары §1, проверяются на Mock-адаптере):

1. Каждая list→detail ссылка пары несёт `return` = адрес источника
   (unit-тест на сборку: `project:gcw` выживает двойное кодирование).
2. На детали: контроль ведёт на `return`; подпись — `routeTitle` источника;
   `aria-label` = «Назад: {место}» (RU/EN).
3. Возврат восстанавливает **весь** URL-стейт источника (фильтры, страница/
   offset, `?tag=`, `?q=`, `?scope=`) — e2e: DOM-список идентичен до ухода.
4. Direct-open без `return`: контроль = фолбэк корня домена; ничего не падает.
5. `return` на внешний путь, `//`, схему или сам себя — отброшен, фолбэк
   (unit-тесты на правило 2).
6. Смена вкладки задачи сохраняет `return`; SSE-поток задач и refetch его не
   трогают; freeze-gate (`TasksLayout.freeze.test.tsx`) зелёный.
7. Browser back не деградировал: POP + восстановление скролла (ScrollRestoration).
8. Клавиатура: контроль первый в строке, фокус-кольцо видно, цель ≥24px;
   trails детальной страницы = «домен › сущность» (средняя ложная крошка
   «Список→/tasks» удалена).

Паро-специфичные (минимум для демо):

9. Сценарий владельца: `/memory/tags?tag=project:gcw` → задача → «‹ Теги» →
   дрилл того же тега (задачи+записи) восстановлен.
10. Архив: строка стала ссылкой на задачу (с `return`); возврат «‹ Архив»
    восстанавливает offset и фильтры.
11. Поиск `?q=mnemos` → запись → «‹ Поиск» → запрос в строке и выдача на месте.
12. Агенты → задача (`?tab=execution&return=/agents/execution…`) → «‹
    Исполнение» → лента на месте; вкладки задачи возврат не съели.

## 5. Срез реализации и что НЕ делаем

**W1 — ядро (~0.3 волны)**: хелпер сборки/валидации `return` (чистые
функции + unit-тесты); back-контроль в `Breadcrumbs`/`Shell`; сокращение
детальных trails в `crumbsFor` (снятие несоответствия «Список»); проводка
пар 1–4 + вкладки задачи; i18n §3.4; state-матрица контрола в тестах.
**W2 — все домены (~0.2–0.3 волны)**: пары 5–13 (дрилл тегов, поиск, пульс,
сессии, агенты, автоматизация), удаление старых `BackLink`, e2e-сценарии §4.9–12.
Серверных зависимостей нет; будущие пары (enrollment) — подключением без
нового проектирования.

Не делаем: `history.back()`-кнопку; sessionStorage/localStorage память
списков; скролл-восстановление для PUSH-возврата (только browser back);
`return` на сайдбаре/TopBar/крошках-секциях; показ фильтров в trails;
`return` в docs (там prev/next); канонические редиректы URL; новые
цвета/шрифты/токены; изменения роутинга и маршрутов.

## Self-review дизайнера (протокол two-pass)

**Пасс 1 (план)**: `return`-параметр на всех list→detail ссылках + ведущий
back-контроль в липкой крошечной строке + сокращение детальных trails.

**Пасс 2 (самокритика)**: «это же browsers-back-кнопка из 2008-го?» — нет:
контроль не replay-ет историю, он **контекстная ссылка** с предсказуемым
адресатом и видимым именем источника; browser back остаётся путём с
скроллом. Отвергнуто в пассе 2: доменная память (b) — воспроизводит боль для
кросс-доменных входов, которых в инвентаре 5 из 13; `history.back()` (c) —
третий сценарий с detail→detail делает его ложью; текст-лейбл «Назад» без
адресата — провал 2.4.4 при нескольких уровнях. Опознаётся без брендинга
лишь связкой «return в ссылке + имя источника как подпись + фолбэк без
