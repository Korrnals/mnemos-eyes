## 2. Информационная архитектура (матрёшка)

Таксономия подтверждена договором тегов (fixtures `mem-0004`: «all mnemos
tags use namespaced prefixes — project:, agent:, mnemos:, topic:; free-form
rejected»). Уровни:

```
Ур.0  Корпус         «610 тегов · данные на 14:02 · 2 из 3 хранилищ»
Ур.1  Семейства      чип-ряд фильтра: mnemos · agent · project · gcw · topic · …
                     (семейство = первый сегмент до ":"; без ":" → «без префикса»;
                      список семейств строится ИЗ ДАННЫХ, не хардкодится)
Ур.2  Диапазоны      секции облака: Ядро 1000+ · Частые 100–999 · Средние 10–99 · Редкие 1–9
Ур.3  Цепочки        внутри семейства: группы по второму сегменту
                     (gcw: → component: → skills) — префиксные цепочки
Ур.4  Дрилл          ?tag=… → задачи борда + записи + «рядом в семействе»
```

Два режима обзора — **одна ось группировки за раз**:

- **Вид «частоты»** (семейство = Все): вертикальный ритм — секции диапазонов
  (§3), внутри — чипы. Это стартовый вид: отвечает «что важно в корпусе».
- **Вид «таксономии»** (выбрано семейство): группы по сегментам для тегов с
  ≥2 двоеточиями (метка группы `component:` + её чипы, сортировка по массе),
  одно-сегментные теги семейства — общей группой сверху. Отвечает «что
  внутри project / gcw» — сценарий владельца «проваливаемся в project →
  там варианты с проектами».

Переход Ур.2→Ур.4: клик по чипу тега (любого размера). Переход Ур.1→Ур.3:
клик по чипу семейства. Хвост сворачивается капом на раскрытие (§3.3), а не
скрытием: «+N ещё» всегда виден в каждой секции.

## 3. Механика диапазонов частоты (ядро спеки)

### 3.1 Отказ от предложений (self-critique входа)

| Вариант | На 610 тегах с max 1141 | При росте ×10 (6100, max ~11k) | Вердикт |
| --- | --- | --- | --- |
| Фиксированные диапазоны владельца 0–100 / 101–500 / 501–1000 / 1001+ | ~545 тегов (90 %) в корзине 1–100 — **простыня переезжает в корзину**; в трёх верхних ~5–7 тегов суммарно | корзина 1001+ сама становится простынёй; 101–500 пустеет | отклонён: не группирует там, где надо, и не масштабируется |
| Квантили по рангу (равные доли тегов) | рендер стабилен, но подписи корзин — «37–41 включений» — перетасовываются на каждом refetch; не читается как «диапазон частоты» | то же | отклонён как основа; ранг оставлен как механизм капов (§3.3) |
| Лог₂-бин (1,2,4,…,1024) | 11 корзин; середина (512–1024) с 1–3 тегами, низ (1–2, 2–4) — новые простыни | 14 корзин, дыры в середине | отклонён: слишком мелкий шаг |
| **Лог₁₀-магнитуды: 1–9 / 10–99 / 100–999 / 1000+** | 4 корзины, человекочитаемые пороги (единицы/десятки/сотни/тысячи), каждая непуста на якорях | добавляется ровно одна корзина сверху (10k+), население сдвигается на уровень, середины не пустеют | **принято**, см. §3.2 |

### 3.2 Формула

Корзина тега = `floor(log10(count))`, кламп 0..3+: пороги 10⁰=1, 10¹, 10², 10³.
Подписи — живые, из данных: заголовок секции «Частые · 100–999» + счётчик
«{n} тегов» (реальные min/max корзины не показываем — пороги стабильны,
значения внутри дёргаются).

**Запрет пустых корзин — правило drop-empty:** секция с нулём тегов не
рендерится вообще (никаких «0 тегов»). Пороги не требуют ни одной заполненной
корзины: на свежем корпусе, где все теги 1–9, честно рендерится одна секция
«Редкие». Магнитудные корзины могут опустеть только на разрыве распределения
(напр. 150 → 8 без середины) — drop-empty покрывает и это.

**Почему магнитуды, а не ранги, — принципиально:** пользователь решает задачу
«насколько этот тег важен в корпусе» — это абсолютная частота, у неё
естественная логарифмическая психофизика (разница 340 vs 419 нечитаема,
340 vs 34 — читаема). Ранг — инструмент рендера (капы), не подпись.

### 3.3 Капы на хвост (анти-простыня внутри корзины)

- Секция рендерит **≤24 чипов** изначально (сортировка count DESC, name ASC —
  существующее детерминированное правило).
- `≤24` тегов — полный рендер, без контрола.
- `25–48` — контрол «Показать все {n}» (одно раскрытие).
- `>48` — инкремент «Ещё 24 из {n}» шагами по 24; после первого раскрытия
  появляется «Свернуть» (возврат к 24).
- Поиск (§4) обходит капы: активный фильтр заменяет секции одним плоским
  ранжированным списком (кап 100 результатов + «уточните запрос»).

Бюджет DOM: ≤ 4 секции × 24 чипа + заголовки + чип-ряд семейств ≈ **~110
интерактивных нод** при любом N (сейчас ~1220 на 610 тегах).

### 3.4 Расчёт на данных

Zipf-подгонка по якорям: `count(r) ≈ 1141·r^−0.583` (s из рангов 1→8:
ln(1141/340)/ln 8). Оценки:

| Корзина | Модель (чистый Zipf) | Реалистичный коридор (хвосты реальных корпусов тяжелее в единицах) |
| --- | --- | --- |
| Ядро 1000+ | r ≤ 1.25 → **1** (`mnemos:checkpoint`) | 1 |
| Частые 100–999 | r 2–65 → **~64** | 40–65 |
| Средние 10–99 | r 66–610 → **~545** (модель переоценивает хвост: count(610) ≈ 27) | 280–500 |
| Редкие 1–9 | **0** (артефакт модели) | 50–250 |

Модель надёжна на голове (первые две корзины) и врёт на хвосте — поэтому
механика построена так, что **раскол B1/B0 не влияет ни на что**: капы
держат обе корзины, drop-empty прячет пустую, подписи порогов фиксированы.
FE-верификация (§0) закроет коридор фактом.

Рост корпуса ×10 (N≈6100, max≈11.4k): появляется Ядро-10k (≈1), 1000+
наследует население сегодняшних «Частых» (~40–65), и т. д. — один новый
заголовок сверху, ноль изменений механики, ноль пустых середины, DOM-бюджет
не меняется.

## 4. Облако: визуальная механика, a11y, клавиатура, поиск

### 4.1 Кодирование

- **Размер = частота, шагами по корзине** (не непрерывно): Ядро — `--text-base`
  `--weight-medium`; Частые — `--text-sm` `--weight-medium`; Средние —
  `--text-sm`; Редкие — `--text-xs`. Обоснование: непрерывный лог-скейл на
  1..1141 даёт неразличимые размеры (разброс ln ≈ 7); 4 шага совпадают с
  секциями — кодирование одно, а не два конкурирующих. Внутри корзины чипы
  равны — разница внутри корзины незначима, и врать размером мы не будем.
- **Цвет = существующая карта** `tagVariant` (iris для `mnemos:`/`type:`,
  confidence/error — контрактные спецслучаи, остальное нейтрально). Семейство
  НЕ кодируется новым цветом (ADR 0003: новых цветов нет; WCAG 1.4.1 —
  префикс виден текстом в самом чипе). Семейство живёт в чип-ряде фильтра.
- Счётчик внутри чипа: `--text-xs`, `--color-text-secondary` на поверхности
  well (≥4.5:1). Чип: `--radius-sm`, поверхность well, бордер subtle;
  hover — фон elevated; focus-visible — существующий паттерн TagBadge
  (outline-iris-bright 2px, offset 2).
- Секции — типографика, не карточки: маркер ▌ (`--color-iris-dim`, 2px),
  подпись `--text-sm` `--weight-medium`, счётчик `--text-xs` secondary,
  отступ `--space-6` между секциями. Один «смелый» элемент страницы —
  крупный чип Ядра; всё остальное тихое.
- Длинные имена (`agent:gcw-agent-architect`, 25 символов): префикс не
  усекается никогда; на узких экранах чип переносится целиком на новую
  строку (flex-wrap), `max-width: 100%`, эллипсис только хвоста листа,
  полное имя — в `aria-label`.

### 4.2 Клавиатура и скринридер

- Каждый чип — `<button>` в `<li>` внутри `<ul>` секции (семантика списка —
  сначала HTML, ARIA только там, где HTML не выражает: `aria-expanded` на
  контроле раскрытия). Естественный Tab-порядок: фильтр → чип-ряд семейств →
  секции сверху вниз.
- Секция — `<section aria-labelledby>`; фильтр-инпут `type="search"` с
  существующим лейблом; результат фильтрации объявляется `aria-live=polite`
  («Подходит: 12»).
- Цели касания ≥24×24 (WCAG 2.5.8): чипы Редких (`--text-xs`) получают
  вертикальный паддинг до `min-height: 24px`; контролы раскрытия —
  стандартная высота кнопки.
- Reflow (WCAG 1.4.10): на 320px чипы переносятся, горизонтального скролла
  нет; чип-ряд семейств скроллится горизонтально как едиственный
  допустимый случай (с `overflow-x` и видимым affordance затухания).
- Фокус не перекрывается (WCAG 2.4.11): никаких sticky-элементов на
  странице кроме апп-шелла.

### 4.3 Поиск

Существующий `TagFilterInput` (подстрока, case-insensitive) + два уточнения:
prefix-совпадение ранжируется выше вхождения (`project:g` → `project:gcw`
раньше `phase:project-cleanup`); активный фильтр = плоский ранжированный
лист (§3.3), совпадение выделяется `--weight-medium`. Очистка фильтра
возвращает секции с сохранёнными раскрытиями.

### 4.4 Motion (хореография)

- Один оркестрованный момент: вход секций при первой загрузке —
  stagger 40ms (`--duration-stagger`), fade + подъём 4px, 150ms
  (`--duration-fast`, `--ease-out`), не более 4 секций.
- Раскрытие секции: высота+fade 150ms; переход в дрил: crossfade контента
  150ms, без shared-element-театра.
- Refetch-реконсиляция: только смена текста счётчика (80ms,
  `--duration-instant`); пересечение тегом порога корзины НЕ перетасовывает
  DOM в живой сессии — состав корзин считается по снапшоту фетча
  (freeze-рамка; урок 1.1.4: обновления не ломают свёрнутые состояния).
- Всё гасится `prefers-reduced-motion` (глобальные токены уже обнуляют
  `--duration-*`; спека это наследует, ничего дополнительного).
- Hover-движение только смена цвета фона чипа — никакого
  hover-every-chip transform.

## 5. Drill-цепочка (матрёшка)

Маршрут: существующий query-параметр `?tag=` (deep-link уже работает),
семейство — `?family=`. Содержимое — v0 строго на существующих эндпоинтах:

1. **Шапка**: тег (моно), счётчик из кэша `/api/tags`, чип семейства.
2. **«Рядом в семействе»**: топ-12 префикс-сиблингов по счётчику
   (клиентски из `/api/tags`, полный и честный источник) — боковой ход
   матрёшки без нового запроса. Для тегов с ≥2 двоеточиями — дополнительно
   ссылка «Группа {второй-сегмент}» → вид таксономии (Ур.3).
3. **Задачи борда**: из `GET /api/tags/{tag}/drill` → `tasks[]`
   (id, title, col, agents, env) — ссылки на `/tasks/:id`. Это новый
   источник ценности: семейство `task:*` и `project:*` связаны с бордом.
4. **Записи**: из drill → `memories[]` (title, tags, server, created_at,
   status, excerpt) — `MemoryCard`, ссылки на `/memory/:id`, бейдж сервера.
5. **Честность BE-13**: drill ищет через `POST /search` (гибридный ранжир,
   известный недобор — задокументирован в `server/task_inbox.py:32–38`).
   Подпись под списком: «показано подмножество…». Счётчик тега в шапке —
   из `/api/tags` (полный); расхождение видно и объяснено. Закрытие BE-13
   (переход на `GET /memories?tags=`) убирает только подпись, не вёрстку.
6. **«Открыть в Записях»** → `/memory?tag={tag}` (концепт §2.2 это уже
   обещает; FE-зависимость: если `parseMemoryListParams` не читает `tag` —
   добавить, это viewer-параметр, не новый эндпоинт).

Замена текущего клиентского фильтра 500 записей на серверный drill —
обязательна: текущий путь теряет записи за пределами свежих 500 и не видит
задач вообще.

## 6. State-матрица

| Состояние | Условие | Вид | Копия (ключ) |
| --- | --- | --- | --- |
| loading | первый фетч `/api/tags` | скелетоны секций (2 контура + чип-ряд), `role=status` | `tags.loading` |
| error | `/api/tags` упал целиком | EmptyState error + «Повторить» | `tags.loadFailed` |
| **partial** | `errors[]` ≠ ∅ (упали не все сторы) | жёлтая точка `◐` в строке статистики + tooltip со списком сторов; облако рендерится из ответивших | `tags.partialData` |
| **stale / refresh** | refetch в полёте (старение 60s, refocus, ручной) | контент не мигает; по завершении — тихая смена счётчиков; реконсиляция по имени тега (stable key), не по индексу; свёрнутости/раскрытия не трогаются | `tags.statsLine` (время обновляется) |
| empty (корпус пуст) | 0 тегов | EmptyState + пояснение | `tags.noTags` / `tags.noTagsMessage` |
| filter-empty | фильтр без совпадений | плоский лист → EmptyState | `tags.noMatch` / `tags.noMatchMessage` |
| drill loading | фетч drill | скелетоны MemoryCard ×3 | `tags.loading` |
| drill error | drill упал | EmptyState error + «Повторить» | `tags.loadFailed` |
| drill empty | `tasks=[]` и `memories=[]`, счётчик >0 | обе группы со своими empty-строками + подпись о подмножестве (BE-13) | `tags.drill.tasksEmpty` |

SSE: в словаре `/api/events` (ui-contract §11) теговых событий **нет** —
свежесть только через staleTime/refocus/ручной; SSE-reconnect не триггерит
рефетч тегов. Введение `memory.changed`-kinда — будущее SE-предложение
(§7.3), не часть v0.

## 7. Графовая перспектива (честно: что НЕ делаем)

### 7.1 v0 — без графов

- Связи тегов = **префиксная таксономия** (клиентская структура над
  `/api/tags`): семейства, сегмент-группы, сиблинги. Полные, детерминированные,
  ноль новых запросов.
- **Co-occurrence НЕ строим**: drill-ответ содержит `tags[]` записей, но по
  ≤12–25 ранжированным записям на стор — «похожие теги» на таком срезе
  врали бы подмножеством. Честный co-occurrence требует либо серверного
  агрегата, либо полного скана — не v0.

### 7.2 v1 — критерии триггера (когда graph-expansion / task-queue-mnemos-128 материализуется)

1. Появился серверный примитив tag→tag рёбер (memory-edges), с честным
   агрегатом по всем сторам.
2. У владельца есть реальный вопрос, который таксономия не покрывает
   («что связано с X вне его префикса»).
3. Не раньше разблокировки слота L2 `/memory/clusters` (ADR 0003 D12) —
   граф-навигация тегов должна жить там, а не плодить вторую графовую
   страницу (урок ai-brain §8.6).

Тогда: в дрилле «Рядом в семействе» дополняется блоком «Связанные»
(рёбра с весом), вёрстка не меняется. Mesh-ноды (`GET /api/mesh/nodes`) —
федерация серверов, не субстрат тегового графа: не трогаем.

### 7.3 Что НЕ делаем в v0 (списком)

Граф-вью, co-occurrence из drill, кластеризация, новые эндпоинты, новые
цвета/шрифты, SSE-события тегов, per-тег анимации. Слот IA не расширяется:
один маршрут `/memory/tags` + query-параметры.

## 8. Уроки ai-brain (`app.js:3084–3144`, `app.css:612–644`)

Что там было: страница тегов = flex-wrap «облако» одинаковых чипов + чекбокс
«показать служебные» (`ext:*`, `project:*` скрыты по умолчанию) + правый
клик-контекст-меню (просмотр/фильтр/удалить все) + hash-роут дрилла.

| # | Урок | В спеке |
| --- | --- | --- |
| 1 | «Облако» без кодирования частоты (чипы одного размера) — частота невидима | размер шагами по корзине + секции диапазонов (§4.1) |
| 2 | Двоичный сплит «семантические/служебные» чекбоксом: грубо; у нас префиксные семейства — главный навигационный актив, прятать их — выпотрошить страницу | семейства — первичный фильтр-ряд, без сокрытий (§2) |
| 3 | Хвост рендерился целиком — простыня в другом платье | капы + инкремент (§3.3) |
| 4 | Контекст-меню только на правый клик — недоступно с клавиатуры | все действия — видимые кнопки/ссылки (§4.2) |
| 5 | Состояние чекбокса не переживало перезагрузку | фильтр семейства и раскрытия — в URL/персистентном состоянии, back восстанавливает (§2.2, §5) |

Взять из ai-brain: deep-link дрилла, breadcrumbs, счётчик внутри чипа,
идею деления по префиксам — но как фильтр-навигацию, не как мусорку
«служебных».

## 10. Требования к данным/контрактам (для SE — ничего нового)

1. `GET /api/tags` — как есть (`TagListOut`: count, items[{name,count}],
   errors[]; сервер уже суммирует по сторам).
2. `GET /api/tags/{tag}/drill?limit=` — как есть (tasks[], memories[],
   errors[]); FE кладёт в gateway-интерфейс (`MemoryGateway` + Http/Mock/
   Board адаптеры) рядом с `listTags`.
3. BE-13 (переезд drill на `GET /memories?tags=`) — серверный тикет уже
   есть; UI-влияние — убрать `tags.drill.subsetNote`, ничего больше.
4. `?family=` — viewer-параметр; `/memory?tag=` — расширение
   `parseMemoryListParams` при отсутствии (FE-зона).
5. Фикстуры: в MockAdapter — датасет тегов масштаба 610 (генерируемый
   детерминированно, Zipf-профиль по §3.4), иначе капы/секции не
   протестиировать на правде.

## 11. Критерии приёмки (FE-волна)

1. Облако: 4 магнитудных секции с drop-empty; начальный рендер ≤ ~110
   интерактивных нод на корпусе 610 (замер в тесте по фиксстуре §10.5).
2. Капы: «Показать все/Ещё 24/Свернуть» работают пошагово; после
   back-навигации из дрилла раскрытия, фильтр, семейство и скролл
   восстановлены (e2e-сценарий).
3. Семейство: чип-ряд из данных (первый сегмент), вид таксономии с
   сегмент-группами для ≥2-двоеточных тегов; семейство «без префикса»
   присутствует, если такие теги есть.
4. Дрилл: `?tag=` использует серверный drill (tasks + memories + server
   badges); подпись подмножества рендерится; «Рядом в семействе» — топ-12
   сиблингов из `/api/tags`; deep-link `/memory/tags?tag=project:gcw`
   воспроизводим.
5. Клавиатура: от фильтра до любого чипа и обратно — без мыши; раскрытия
   — `aria-expanded`; фильтр объявляет число совпадений (aria-live).
6. Контраст/цели: счётчики ≥4.5:1 на well; чипы Редких ≥24px высоты;
   фокус-кольцо iris-bright не перекрывается. Новых цветов/шрифтов — ноль
   (токен-тест).
7. Состояния матрицы §6 демонстрируемы на Mock-адаптере (loading/partial/
   error/empty/filter-empty/drill-подмножество).
8. Верификация §0 (jq-гистограмма живого API) приложена к PR; при
   расхождении коридора §3.4 >±30 % — корректируются только константы
   капов, не механика (эскалация дизайнеру, если не помогает).
9. i18n: все строки §9 в ru.ts и en.ts; захардкоженных строк нет.
10. Reduced-motion: вход секций/раскрытия без анимации.

Волна/срез: один FE-срез ~0.6–0.8 волны (модуль tags-cloud + ревайринг
дрилла + i18n + фикстуры + тесты/e2e). Серверных зависимостей нет; BE-13
закрывается параллельно серверной командой.

## Self-review дизайнера (протокол two-pass)

**Пасс 1 (план)**: магнитудные секции + чип-ряд семейств + размер шагами;
дрилл на серверный эндпоинт с сиблинг-стрипом.
**Пасс 2 (самокритика)**: «это же просто TagCloud из туториала?» — нет:
опознаётся без брендинга по тройке «магнитудные секции с живыми счётчиками +
префиксные семейства как навигация + честная подпись подмножества BE-13»;
obsidian-well фон, iris-фокус, моно-теги — системные, не добавленные.
Отвергнуто в пассе 2: кодирование семейств цветом (ломает ADR 0003 и
1.4.1 — префикс и так текст); непрерывный размер шрифта (лжёт различием
340 vs 419); sticky-панель фильтров (перекрывает фокус, 2.4.11);
ко-вхождение из drill-подмножества (нечестно). Anti-slop: секции —
типографика с маркером, не карточки-плитки; смелость одна — Ядро; даш-
эстетики нет (строка статистики — честность, не сводка ради сводки).
**Открытые допущения**: коридор B1/B0 (§3.4) закрывается верификацией §0;
если `parseMemoryListParams` не знает `tag` — FE добавляет (§10.4).
