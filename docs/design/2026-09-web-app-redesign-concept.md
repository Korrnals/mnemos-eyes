### 1.2 Что предел — дашборд-паттерн

1. **Всё в одном экране.** Борд = один канбан + правая рельса на 8 блоков
   (Хранилища, Кластеры, Входящие, Архив, Агенты, Специалисты, Среды, Пульс).
   Рельса — это вырожденный sidebar, в котором «Пульс памяти» — data-heavy
   страница — живёт в аккордеоне с `max-height: 300px`. Архив — страница
   истории — живёт в модалке с пейджером. Каждый следующий блок рельсы
   делает остальные хуже: это архитектурный, а не косметический предел.
2. **Модальный стек вместо навигации.** `ui-contract.md` §2–3 построены вокруг
   `ddStack`/`modalHistory`: сущности открываются оверлеями друг над другом.
   Следствия: (а) **нет URL** — нельзя дать ссылку на задачу/память/тег,
   нельзя закладку, нельзя восстановить сессию после F5; (б) глубина
   погружения ограничена стеком и вниманием; (в) a11y-стоимость растёт с
   каждым уровнем (фокус-трапы вложенных диалогов). Владелец сам решил эту
   проблему в ai-brain — hash-роутером и breadcrumbs: паттерн доказан
   владельцем, борд его не имеет.
3. **Канбан как единственный вид задач.** Канбан хорош для *потока* (что в
   работе, что застряло), но не для *управления массой*: bulk-операции,
   сортировка по приоритету/возрасту, поиск по задачам, просмотр отчётов
   всех задач, валидация WF-1 (24-часовые часы на колонке) — всё это виды
   «списка/таблицы», которых нет. Фильтрбар частично компенсирует, но
   фильтрация ≠ альтернативная проекция.
4. **Нет клавиатурного слоя.** Ни `/` поиска, ни палитры команд, ни
   навигации по спискам. Для операционного кокпита, который владелец держит
   открытым весь день, это ежедневная потеря.
5. **Нет i18n-слоя.** Подписи захардкожены вперемешку (русские подписи +
   английские термины) — ai-brain уже прошёл этот путь и вынес словарь
   (`I18N`-объект, 350+ ключей на язык); урок: словарь вводится в день
   один, а не ретро-инвентаризацией.
6. **Два фронтенда с разными IA.** Борд (операционный, вертикально-узкий) и
   L1-вьювер (просмотр памяти, 7 плоских роутов) не образуют приложения —
   они два инструмента с общими токенами. Вопрос ADR 0006 обостряется:
   каждая новая сущность (assignment, inbox, mesh, QR) не имеет очевидного
   «своего» фронтенда.

**Вывод.** Дашборд-паттерн исчерпан не потому, что «некрасиво», а потому что
функциональная карта (5 доменов, ~20 страниц, ~10 флоу) перестала помещаться
в один экран + рельсу + модальный стек. Дальше — только вложенная IA со
страницами, URL и вложенностью 2–3 уровня.

## 2. Информационная архитектура

### 2.1 Карта приложения (одной схемой)

```
vesmaro-eyes web app
│
├── Обзор (Home, "/")                     — «взгляд в себя»: колодец + сводка доменов
│
├── Память /memory
│   ├── Поиск        /memory/search       — pupil-focus, fts|semantic|hybrid
│   ├── Пульс        /memory/pulse        — live-лента, группировка проект→сервер
│   ├── Записи       /memory, /memory/:id — мастер-детейл: список/таблица ↔ scroll; bulk
│   ├── Теги         /memory/tags         — инспектор; клик → фильтр Записей
│   └── Кластеры     /memory/clusters *   — L2: граф (ADR 0003 D12), слот скрыт
│
├── Задачи /tasks
│   ├── Канбан       /tasks/board         — 7 колонок WF-1, группы-аккордеон, DnD
│   ├── Входящие     /tasks/inbox         — AGG-1 проекции task:queue, adopt
│   ├── Отчёты       /tasks/reports       — сквозная лента отчётов всех задач
│   ├── Архив        /tasks/archive       — группировка по проектам, поиск, restore
│   └── Задача       /tasks/:id           — страница задачи: Обзор·память / Отчёты / История
│                                          + Исполнение (assignments, ARCH-2)
│
├── Агенты /agents
│   ├── Исполнение   /agents/execution    — assignments live: очередь/активные/heartbeat,
│   │                                       нижняя панель UI-10 (лента событий исполнения)
│   ├── Специалисты  /agents/specialists  — реестр + /agents/specialists/:name (профиль)
│   └── Харнесы·среды /agents/harnesses   — ADR 0005: harness ≠ specialist; среды
│
├── Хранилища /stores
│   ├── Реестр       /stores              — серверы: здоровье, статы, подключение
│   │                                       + /stores/:name (карточка: stats/история/форма)
│   ├── Группы       /stores/groups       — кластеры памяти (merge-области), состав
│   └── Mesh         /stores/mesh *       — MSH-1: статус федерации (ADR 0007)
│
└── Система /system
    ├── Уведомления  /system/notifications — все/рабочие/системные (колокольчик = вход)
    ├── Устройства   /system/devices       — QR-пейринг (§6)
    └── Настройки    /system/settings      — тема, язык (RU/EN), плотность, хоткеи-подсказка
```

`*` — слот существует в IA, контент включается по готовности бэкенда
(кластеры — L2, mesh — MSH-1). Принцип: **пустой слот не рендерится**
(как nav-слот Clusters в L1 сегодня), «скоро» — не показываем.

Правила вложенности:

- **Уровень 1** — домен (sidebar, 5 доменов + Обзор как корень).
- **Уровень 2** — страница-раздел внутри домена (табы верхнего уровня страницы).
- **Уровень 3** — детальная страница сущности (`/memory/:id`,
  `/tasks/:id`, `/agents/specialists/:name`, `/stores/:name`) или
  дровер-«подглядывание» без потери контекста списка.
- Глубже 3 уровней — запрещено: это сигнал, что сущность требует своего
  домена.

### 2.2 Навигационная схема

**Составляющие (все вместе):**

1. **Доменный sidebar** (слева, 220px, сворачивается до 56px icon-only
   на узких экранах — паттерн ai-brain). 5 доменов + Обзор. Активный домен
   подсвечен iris; внутри домена подразделы показываются под доменом
   (не третий уровень в sidebar — sidebar остаётся двухслойным:
   домен → раздел).
2. **Breadcrumbs** на каждой странице уровня 2–3: `Память / Записи /
   <auto-title>` — паттерн ai-brain (последний элемент — не ссылка).
   Breadcrumbs кликабельны на весь путь вверх — это дешёвый способ
   «выйти на уровень» без кнопки «Назад».
3. **Глобальный поиск в топбаре** (не в странице): `/` фокусирует,
   placeholder «Поиск по памяти и задачам…». Enter → `/memory/search?q=…`.
   Это объединяющий вход памяти и задач (см. §4.3).
4. **Командная палитра** `Ctrl+K` (см. §4.4): переходы, действия, сущности
   по id. Для «подпрограмм» — главный ускоритель.
5. **Status-пилюли топбара** (справа): SSE-live, активные assignments
   (счётчик + пульс при running), непрочитанные уведомления, тема. Паттерн
   ai-brain `header-job-pill` (poll активной job в хедере, busy-стиль) —
   переносим на SSE-словарь: `assignment.started/done/failed` двигают
   пилюлю без поллинга.
6. **Хоткеи**: `/` — поиск; `Ctrl+K` — палитра; `j/k` — движение по
   спискам; `x` — выделение строки; `Ctrl+A` — выделить видимое; `Del` —
   удалить выделенное (с подтверждением); `?` — шпаргалка хоткеев;
   `g`-префикс (`g m` — Память, `g t` — Задачи, `g b` — Канбан…) —
   доменные прыжки. Все хоткеи отключаются в полях ввода (правило ai-brain
   `inInput`-guard).
7. **Контекстные меню (правый клик)** — канон `ui-contract.md` §5
   сохраняется как второй путь к тем же действиям (распознавание вместо
   припоминания: и палитра, и меню, и кнопка ведут к одному действию).

**Что заменяет модальный стек:** drill-down тега/агента (сегодня `#dd-modal`
+ `ddStack`) становится **роутом с контекстом**: тег → `/memory?tag=…`
(или `/tasks?tag=…` — с переключателем «память|задачи» над результатами);
агент → `/agents/specialists/:name`. «Подглядеть» без ухода — дровер
(§4.2). Правило «новые вкладки запрещены» сохраняется — всё в одном app.

**ASCII-схема оболочки (ключевая поверхность):**

```
┌──────────────────────────────────────────────────────────────────────────┐
│ ◉ vesmaro-eyes   [ ⌕ Поиск по памяти и задачам…  / ]    ⟳live ▸2⚡ 🔔 ◐ │ ← топбар
├────────────┬─────────────────────────────────────────────────────────────┤
│ ◉ Обзор    │  Память / Записи / T-128 «UI-10 проводник»      [⋮] [⤢]    │ ← breadcrumbs
│ ● Память   │  ┌─────────────────────────────┬───────────────────────────┐│
│ ○ Задачи   │  │ список/таблица              │ scroll (Lora, вед-relaxed)││
│ ○ Агенты   │  │ ☑ …  [bulk-тулбар при ☑]   │ provenance · ●conf 0.92   ││
│ ○ Хранилищ │  │ … мастер                    │ tags → /memory?tag=…      ││
│ ○ Система  │  │ … (scroll-restore)          │ raw-toggle / метаданные   ││
│            │  └─────────────────────────────┴───────────────────────────┘│
```

### 2.3 Судьба канбана

**Канбан остаётся, но перестаёт быть главным экраном. Он — вид №1 домена
«Задачи»** (`/tasks/board`), потому что поток работы — главный сценарий
домена. Изменения:

- Колонки расширяются до линейки WF-1:
  `backlog → validating → open → in-progress → blocked → resolved → done`
  (часы `validating` — таймер-бейдж на карточке и колонке; archcom-ветка —
  визуальный маркер `task:stage:archcom-review`).
- Группы-аккордеон по проектам сохраняются (доказано UI-14), свёрнутость —
  персистентна.
- Переключатель вида внутри домена: **Канбан | Список** (таблица:
  приоритет/возраст/проект/assignment, bulk, сортировки) — список закрывает
  «управление массой», канбан — «поток».
- Перетаскивание дополняется **клавиатурным эквивалентом** (контекст-меню
  «Переместить в…» + пункт в странице задачи) — WCAG 2.1.1.
- Стартовая страница домена «Задачи» = Канбан; «Обзор» (Home) показывает
  только срез (топ-блоки, см. §2.4).

**Главный экран приложения — «Обзор»**, не канбан: сводка требует места
над доменами (задачи ждут валидации + задания без пульса + недоступный
store + свежий пульс). Канбан как Home повторял бы ошибку «один экран =
одна проекция».

### 2.4 Страница «Обзор» (Home)

Верх — «колодец» (signature-момент, §3.2): iris-герой + глобальная строка
поиска. Ниже — 4 компактных блока-карточки доменов, каждый — «что требует
внимания» + счётчики, клик — переход в домен:

- **Задачи**: validating с тикающими часами, blocked, resolved ждёт
  приёмки, inbox-счётчик.
- **Агенты**: активные assignments (state + возраст heartbeat), failed/
  expired за сегодня.
- **Хранилища**: здоровье серверов (точки канона §7 ui-contract),
  недавние события sync.
- **Пульс**: 3–5 последних записей с provenance, «все →».

Правило против дашификации: на Обзоре **нет** графиков и счётчиков ради
счётчиков — только элементы, требующие решения или клика. Блок без
содержания не рендерится.

### 2.5 «Подпрограммы» (флоу)

Каждый флоу — последовательность страниц/шагов с URL-состоянием, не
состояние в замыкании модалки:

| Флоу | Шаги | Где живёт |
| --- | --- | --- |
| **Пейринг устройства (QR)** | Настройки → Устройства → «Подключить» → QR + код → одобрение на обеих сторонах → список устройств → отзыв | §6; `/system/devices` |
| **Принятие задачи из инбокса** | Входящие (проекция, read-only, provenance) → «Принять в борд» (adopt: title/project/priority/specialist из записи) → переход на созданную задачу | `/tasks/inbox`; ADR 0010 |
| **Валидация WF-1** | Backlog → «В валидацию» → таймер 24ч на карточке/колонке → исход A (владелец: → open) / B (таймаут: archcom-маркер + уведомление) / C (TL: → in-progress, `validated-by:tl`) | `/tasks/board`, карточка, notifications |
| **Запуск агента (ARCH-2)** | Страница задачи → «Взять в работу» → выбор specialist + harness → assignment `queued` → claim/start (поллер) → running + heartbeat → отчёты тикают в «Отчёты» + панель UI-10 → done/failed/cancelled/expired | `/tasks/:id` + `/agents/execution`; ADR 0009 |
| **Отчёт агента** | Отчёт (intermediate/final, supersede) → лента в задаче, сквозная лента `/tasks/reports`, toast + notification | ADR 0009 §7 |
| **Подключение хранилища** | Реестр → «+» → форма (имя/URL/токен env:|file:) → «Проверить» (дешёвый ping) → сохранить → точка здоровья, авто-восстановление | `/stores`, `/stores/:name` |
| **Черновик задачи** | «+ Новая задача» (топбар/палитра) → модал-черновик (короткая транзакция, не навигация) → mnemos open-question → появится во Входящих | `/` поверх любого роута; ui-contract §12 |

### 2.6 Судьба двух фронтендов (вопрос к архкому по ADR 0006 — UX-аргументация)

**Моя рекомендация: объявить целевой рамкой вариант A (конвергенция в одну
React-оболочку = «web app» в `viewer/`), сохранив freeze-гейты ADR 0006 как
механику перехода.** Фактически — уточнение варианта C: исход «mesh
разрешит сам» теперь известен — не разрешит (ADR 0007 закрепил merge-слой
борда как UI-агрегатор независимо от mesh), значит решение пора назвать.

UX-аргументы за конвергенцию:

1. **URL-first IA невозможна в борде без переписывания**: модальный стек —
   состояние вне адресной строки; добавление роутера в замороженный борд —
   крупнейшее нарушение freeze из возможных. Новая IA по §2.1 требует
   роутинга, вложенных лейаутов и палитры — это React-shell, не vanilla-набор
   обработчиков.
2. **Масштаб IA**: 5 доменов × 2–5 разделов × детальные страницы не
   помещаются ни в рельсу (уже 8 блоков — предел), ни в модальный стек
   (ui-contract §2 сам ограничивает «one full-screen stack at a time»).
3. **Клавиатурно-палитровый слой** (`/`, `Ctrl+K`, `j/k`, `g`-префикс)
   предполагает единый app-shell с фокус-менеджментом — дешево в React
   (роутер + контексты), дорого в vanilla.
4. **A11y-экономика**: страницы/роуты дают семантику документа «бесплатно»
   (заголовки, `history`, фокус на смене роута); каждый уровень
   вложенных диалогов — ручной фокус-трап и ARIA-гимнастика.
5. **Владелец уже владеет паттерном**: ai-brain — страничная SPA на
   hash-роутере с breadcrumbs; страничность не чужая привычка, а
   предпочитаемая.

Аргументы против (честно): (а) риск потерять одобренное поведение
v0.3–v0.9 — митигируется parity-чеклистом ADR 0006 (поведение, не DOM,
переносится: ui-contract §1–9 остаётся поведенческим контрактом);
(б) zero-build простота борда — в кластере публикуется собранный образ, а
не репо, сборка уже есть в `viewer/` (Vite); (в) двойная поддержка в
переходе — ровно это и закрывают freeze + гейт паритета.

Что переносится/не переносится — уже зафиксировано ADR 0006 §4
(контракты/SSE/tokens — да; DOM/JS — никогда). Концепт это только
подтверждает со стороны UX.

## 3. Визуальный язык

### 3.1 Якорь бренда — без изменений

Teal-iris (`--color-iris` #1a8a96) как первичный, gold-confidence как
семантическая пара «ценный сигнал», Lora для контента памяти (ADR 0003
D10–D11), obsidian-well лестница фонов, Inter для UI-хрома. Это
опознаваемый актив с ADR-статусом — редизайн IA его не трогает.

### 3.2 Эволюция: от «спокойного вьювера» к «рабочей утилите, которая дышит»

Design-brief фиксировал настроение «спокойная вода». Перепрофилирование в
операционную утилиту требует уточнения, не отмены:

- **Signature-момент остаётся один и в одном месте**: колодец-герой на
  «Обзоре» + breathing iris (канон «max 1 ambient animation» сохраняется).
  Всё прочее — рабочие поверхности, тихие по определению.
- **Boldness in one place** переносится из «каждый экран — медитация» в
  «Обзор — вход в колодец; дальше — инструмент». Пульс-страница получает
  лёгкую версию глубины (записи всплывают, stagger ≤5 — уже в
  design-system §7), без конкуренции с чтением.

### 3.3 Density-стратегия: два режима чтения (главное решение визуала)

Приложение совмещает несовместимое: **данные-тяжёлые операционные списки**
(задачи, assignments, inbox, теги, trace) и **«взгляд в себя»** (чтение
памяти). Решение — не «выбрать плотность», а **контрастная пара режимов**:

| Режим | Где | Правила |
| --- | --- | --- |
| **Операционный (dense)** | Задачи, Входящие, Агенты, Реестр, Отчёты-лента, Таблицы | строка 32–36px, `--text-sm` (14px), метаданные в строку, минимальные зазоры карточек 8px, моно-цифры (id, таймеры) |
| **Созерцательный (airy)** | Поиск-результаты, Пульс, Записи-список, scroll-детали | строка от 56px, `--text-base`, сниппеты 2 строки, measure ≤72ch, Lora в деталях |

Новые семантические токены (предложение в `tokens.css`, реализация —
@GCW: Senior Frontend Developer): `--row-h-dense` (32px), `--row-h-airy`
(56px), `--list-gap-dense/airy`, `--measure-scroll` (72ch). Плюс
пользовательский тумблер плотности в Настройках (компакт/комфорт) —
двигает только операционный режим.

### 3.4 Заимствования из ai-brain `app.css` — конкретно

**Принять (доказано владельцем):**

1. **Организация токенов семантическими лестницами**:
   `--bg-canvas/primary/secondary/tertiary/hover` + пары
   `цвет + *-muted` (прозрачные подложки бейджей через `color-mix`).
   Это ровно та недостающая часть нашего tokens.css: сегодня бейджи
   статусов в board.css подбирают фоны вручную. Лестница фонов маппится
   1:1 на obsidian-well (`bg-base→canvas`, `bg-well→primary`,
   `bg-elevated→secondary/tertiary`) — расширяет, не ломает.
2. **Глобальный хедер-поиск с `/`-хоткеем и статусной пилюлей**
   (`header-search` + `header-job-pill`): поиск как постоянный вход,
   фоновая занятость — как пилюля с busy-стилем. У нас пилюля питается
   SSE (`assignment.*`, `task.*`), не поллингом.
3. **Breadcrumbs-компонент + «← Назад» в деталях** (`breadcrumbsHtml`):
   последний крамб — не ссылка; на детальной — возврат к источнику.
4. **Bulk-паттерн**: чекбокс-колонка слева от карточки, выбранная строка
   подсвечена iris-подложкой, тулбар действий **появляется над списком**
   при первом выделении, массовое удаление — модал-подтверждение с числом.
5. **Scroll-restore по роуту** (`_scrollPositions[hash]`): возврат из
   детали в список — в ту же точку. Обязателен для мастер-детейла Записей.
6. **Отзывчивый sidebar → icon-only 56px** на ≤768px + скрытие подписи
   бренда — готовая механика для узких экранов.
7. **Организация CSS секциями-маркерами** `/* ── Section ── */` с
   привязкой к номерам фич (board.css уже так делает — продолжаем).

**Не принимать:**

- **GitHub-клон эстетику** (бордово-синий accent `#58a6ff`, GitHub-тёмная
  палитра) — design-brief прямо называет её anti-goal; берём механику
  токенов, не значения.
- **Emoji как иконки** (кнопки `✨ ⚙ ⚡ 🧹 🏷 📝`, health-иконки `📊 🌐 📁 ⚠️`,
  луна/солнце тумблера темы) — заменяем на lucide-набор (уже канон в L1).
- **Градиенты** (progress-fill `accent→cyan` с glow, подложка
  `kb-job-shell`) — канон запрещает; прогресс = сплошной iris- fill.
- **Плоский несгруппированный sidebar на 12+ пунктов** (Dashboard,
  Orchestrator, Memories, Raw, Knowledge, Cache, Jobs, Docs, Projects,
  Catalog, Tags, Watcher, Graph + футер) — предел видимости; у нас
  доменная группировка 5×(2–5).
- **Смешение RU/EN без слоя i18n** — берём сам словарь-паттерн
  (`I18N` + `t(key, vars)` + перерисовка на переключении), вводим с
  первого дня нового app.
- **i18n-плейсхолдеры в value-атрибутах** и инлайн-стили в
  JS-генерации — антипаттерн, в React не переносится по построению.

### 3.5 Палитра — фиксация пер-бриф обоснования

Канон дизайн-направления ограничивает палитру 3–5 цветами; obsidian-well
превышает (4 нейтральных фона + iris 3 ступени + confidence 2 +
success/warning/error/info + 3 текстовых). **Обоснование per-brief**:
(а) статусы — семантическая необходимость (у каждого состояния контракта
свой цвет, дублированный формой/текстом — WCAG 1.4.1); (б) лестница фонов
= метафора глубины колодца, не декоративная палитра; (в) всё уже
зафиксировано ADR 0003 D10 и ui-contract §8. Новых цветов концепт **не
добавляет**; `purple/cyan/orange/green`-варианты ai-brain не переносятся.

Шрифты: 2 семейства + моно для `type:rule|code` памяти — уже оправдано
ADR 0003 D11 (записанное исключение). Моно также используется для
id/таймеров/URL в операционном режиме (тот же JetBrains Mono).

## 4. Компонентная стратегия

### 4.1 Страничные компоненты вместо модалок — принцип перераспределения

| Сущность | Сегодня (борд) | Целевое состояние |
| --- | --- | --- |
| Задача | `#task-modal` (centered, 3 таба) | **Роут** `/tasks/:id`: табы Обзор·память / Отчёты / История / Исполнение; боковая колонка метаданных сохраняется |
| Память | `#dd-modal` (memory view) поверх стека | **Роут** `/memory/:id` (scroll) + дровер-«подглядеть» из списков/задач |
| Хранилище | `#srv-modal` | **Роут** `/stores/:name` (stats/подключение/история) |
| Тег/агент drill | `#dd-modal` + `ddStack` | **Роут-фильтр** `/memory?tag=…`; агент → `/agents/specialists/:name` |
| Специалист | `#dd-modal` (profile) | **Роут** `/agents/specialists/:name` |
| Архив | `#arch-modal` + пейджер | **Роут** `/tasks/archive` (группировки, поиск, restore) |
| Входящие | `#inbox-modal` | **Роут** `/tasks/inbox` |
| Черновик задачи | `#draft-modal` | **Модал остаётся** — короткая транзакция с одним исходом |
| Правка задачи | `#edit-modal` | **Модал остаётся** (включая 423-lock state) |
| Подтверждение опасного | модал | **Модал остаётся** (confirm-диалог) |

Правило: **модалка = короткая транзакция** (создать/подтвердить/быстро
отредактировать), **страница = сущность со своим URL и историей**.
Максимум один модал поверх страницы; стек модалок не восстанавливаем.

### 4.2 Паттерны

- **Мастер-детейл** (десктоп ≥1024px): «Записи», «Специалисты», «Реестр» —
  список слева (фильтры, bulk, scroll-restore), деталь справа; на узких
  экранах — вырождается в список → деталь (навигация).
- **Дровер (side sheet)** для «подглядывания»: превью памяти из карточки
  задачи, превью отчёта из ленты, превью inbox-записи. Закрывается `Esc`/
  кликом мимо/кнопкой; «Открыть полностью» — переход на роут. Дровер не
  накапливает стек: новый подгляд заменяет предыдущий.
- **Командная палитра** (`Ctrl+K`): секции — Переход (домены/разделы),
  Действия (новая задача, сканировать хранилища, сменить scope, тема,
  RU/EN), Сущности (задача по id `T-…`, память по id, специалист по имени).
  Поведение по ai-brain-урокам: фокус в строку при открытии, стрелки +
  Enter, `Esc` закрывает, клик вне закрывает, состояние после действия —
  toast (канон §6).
- **Bulk-операции** (канон из ai-brain, §3.4-4): применяются в Записях,
  Задачах-списке, Входящих (отметить несколько → принять выбранные).
- **Live-лента (Пульс)**: аккордеон проект→сервер (перенос паттерна
  rail-pulse на полноценную страницу), новые записи всплывают сверху с
  400ms-entrance (дизайн-система §7), SSE-обновление без перезагрузки.
- **Нижняя панель UI-10** (исполнение): на `/tasks/:id` и
  `/agents/execution` — раскрываемая панель «что происходило»: лента
  отчётов + assignment-события + (после v0) mnemos-чекпоинты; сворачиваема,
  состояние персистентно.

### 4.3 Глобальный поиск — объединение памяти и задач

Строка в топбаре ведёт поиск по памяти (fts/semantic/hybrid через
merge-слой борда) **и** по задачам (native + inbox). Результаты —
`/memory/search?q=…` с переключателем «Память | Задачи» (по аналогии с
tag-drill: один запрос, две проекции). Отдельная семантика типа поиска
остаётся видимой (badge fts/semantic/hybrid — уже в L1).

### 4.4 Состояние-матрицы ключевых флоу

Канон: каждый интерактивный компонент несёт hover/focus/active/disabled/
error/loading/empty. Ниже — матрицы для новых/изменённых сущностей.
Существующие компоненты L1 (SearchBar, MemoryCard, EmptyState, skeletons)
уже соответствуют и переносятся как есть.

**A. «Взять в работу» (assignment-триггер, ADR 0009 Ф4)**

| Состояние | Вид |
| --- | --- |
| idle | кнопка на `/tasks/:id`; активна если задача в open/blocked-resolved-return и нет активного assignment |
| hover/focus | iris-ободок (`--color-border-iris` + `--shadow-iris`), не перекрыт (WCAG 2.4.11) |
| active | выбор specialist + harness в выпадающей шторке; disabled-пункты = не из allowlist-профиля (подпись почему) |
| loading | «Назначаем…» + iris-пульс кнопки; повторный клик заблокирован |
| success | assignment-бейдж на карточке/странице (state `queued`), toast «T-…: назначено, ждёт поллер», пилюля топбара +1 |
| error | инлайн: 409 (уже есть активный) / 429 (лимит 10/60с) / 403 — конкретный текст, кнопка активна снова |
| disabled | нет ui-token (мутации закрыты) — кнопка видима с пояснением, не спрятана |

**Б. Assignment-бейдж (карточка + страница + `/agents/execution`)**

| Состояние | Вид |
| --- | --- |
| queued | нейтральный контур + возраст («в очереди 4 мин»); stagnation виден — ADR 0009 §4 |
| claimed/running | iris + пульс-точка; «heartbeat N мин назад» рядом; N>10 мин — warning-цвет и подсказка |
| done/failed/cancelled/expired | терминальные (заштрихованный/приглушённый), tooltip с финальным отчётом/причиной |
| identity | всегда «reported by X (unverified)» — ADR 0009 §8, никогда не маскировать |

**В. Adopt из Входящих (ADR 0010)**

| Состояние | Вид |
| --- | --- |
| idle | строка-проекция (read-only, provenance: server/project), кнопка «Принять в борд» |
| loading | строка блокируется, iris-спиннер на кнопке |
| success | toast «Принята → T-…», строка уходит из активного списка (без перезагрузки списка), ссылка на задачу в toast |
| error | 4xx инлайн у строки (например, сервер-источник исчез — «запись больше не видна, сканируйте заново») |
| stale | строка помечена «исчезла из источника», принятие disabled с пояснением |
| empty | «Хранилища просканированы — новых записей `task:queue` нет» + кнопка «Сканировать» (не мёртвый пустой экран) |

**Г. WF-1 валидация (карточка в validating)**

| Состояние | Вид |
| --- | --- |
| validating | таймер-бейдж «⏱ 18:42 до эскалации» (моно, тикает), tooltip правил |
| archcom-ветка | warning-маркер «ждёт уточнения архкома», сортируется вверх колонки |
| переход 409 | toast с подсказкой сервера («blocked → done запрещён: сначала resolved») — текст из API, не выдумываем |

**Д. QR-пейринг (полная матрица — §6).**

**Канон ai-brain-паттернов** — предложение архкому: **принять как канон
нового app** (1) breadcrumbs + back, (2) bulk-select/toolbar/confirm,
(3) scroll-restore, (4) хоткеи с `inInput`-guard. Все четыре
использовались владельцем ежедневно; альтернативных паттернов с такой
проверкой нет.

## 5. A11y / респонсив / motion

### 5.1 WCAG 2.2 AA — именованные критерии и решения

| Критерий | Решение в концепте |
| --- | --- |
| **1.4.3 / 1.4.11** (контраст текста ≥4.5:1, UI ≥3:1) | существующие пары tokens.css сохраняются; новые density-поверхности наследуют; проверка пар в спеке реализации |
| **1.4.10** (reflow 320px без 2D-скролла) | канбан — единственная законная горизонталь (snap-скролл колонок); таблицы → карточный режим <768px |
| **2.1.1** (полная клавиатурность) | каждый флоу имеет клавиатурный путь: DnD-альтернатива (меню «Переместить»), палитра, `j/k/x`, фокус на смене роута |
| **2.4.1** (bypass blocks) | skip-link уже в `Shell.tsx` — сохраняется |
| **2.4.3 / 2.4.7 / 2.4.11** (фокус-порядок, видимость, не перекрыт) | фокус следует за маршрутом; sticky-элементы (топбар, bulk-тулбар) обязаны оставлять фокус-обводку видимой — отступ фокуса в токенах |
| **2.5.8** (цели ≥24×24) | минимум 24px, стремимся к 32px в операционном режиме; на мобильном — 44px |
| **1.4.1** (не только цветом) | статусы всегда = цвет + текст/форма (бейджи с подписью, точки с label) |
| **4.1.2** (name/role/value) | все интерактивы — нативные элементы или shadcn (ARIA по умолчанию); дровер/палитра — `role="dialog"`+`combobox`-паттерны |

### 5.2 Мобильный сценарий (будущее app)

Приоритет сценариев: **просмотр и лёгкие действия** (пульс, канбан
read-only + контекст-меню перемещений, детали задач, уведомления,
QR-пейринг — смартфон как подключаемое устройство), затем мутации.
Принципы: sidebar → нижняя навигация 5 доменов; мастер-детейл →
последовательная навигация; bulk — отложено (жест-мультитач позже);
целевые размеры 44px; canonical viewport без `user-scalable=no` (запрет
канона). Пейринг (§6) проектируется сразу как мобильный first-flow.

### 5.3 Motion

Бюджет design-system §7 сохраняется: **одно амбиентное движение**
(breathing iris, только Обзор/пустые состояния), прочее — отклик на
действие. Новое в концепте: таймеры validating и heartbeat — обновление
цифр без анимации (не отвлекают perиферийно); SSE-всплытие записи в Пульсе
— 400ms entrance, stagger ≤5. `prefers-reduced-motion` — существующие
правила токенов (§7 design-system) + тесты `useReducedMotion` уже в L1.

| **Ожидает одобрения** | состояние устройства между сканом и подтверждением владельца |
| **Одобрить / Отклонить** | решение владельца на стороне vesmaro-eyes |
| **Отозвать** | отключение устройства (revocation), обратимой настройки нет — только новый пейринг |

### 6.2 Флоу (состояния экрана)

```
/system/devices
  ├─ Список устройств: имя · тип · подключено · последний сеанс · [Отозвать]
  │   empty: «Подключённых устройств нет» + [Подключить устройство]
  └─ [Подключить устройство] → шаг 1:
        ┌───────────────────────────────┐
        │  QR (крупно, high-contrast,   │   правила: чёрно-белый QR без
        │  рамка-фокус, TTL-дуга        │   затемнения поверх скрина;
        │  «Код: 8-4-2»  ⏱ 2:00         │   тихая комната = QR виден;
        └───────────────────────────────┘   TTL-дуга угасает, QR ротируется)
        подпись: «Отсканируйте приложением vesmaro-eyes. Совпадает ли код
        на телефоне с показанным здесь?»
  → телефон отсканировал → шаг 2 (на десктопе): «Устройство ожидает
    одобрения · код на телефоне: _ _ _-_ _ _» [Одобрить] [Отклонить]
  → Одобрить → шаг 3: «Подключено: <имя>» + список обновился, toast.
  Отказ/таймаут: честное состояние («Пейринг истёк — начните заново»),
  без молчаливого зависания.
```

### 6.3 UX-требования (для arch3)

1. **QR живёт ≤2 мин и ротируется**; экран не затемняется (wake-lock по
   возможности); контраст QR ≥ 3:1 к подложке.
2. **Числовое сравнение на обеих сторонах** — защита от «отсканировал не
   тот QR» (канал должен подтвердить владение обоими экранами).
3. **Одобрение — всегда явное действие владельца** на уже доверенном
   экране; «автопринятие» не предусматриваем.
4. **Честная идентичность** (ADR 0009 §8-паттерн): устройство без
   верифицированной личности подписывается «unverified» до первого
   сеанса.
5. **Отзыв** — одно действие с confirm (модал, «Устройство потеряет
   доступ. Отменить нельзя — потребуется новый пейринг»), в списке —
   «отозвано N дней назад» до очистки.
6. Доступность: флоу **не может** требовать сканера у Accessibility-Tool
   пользователя — альтернативный ввод пейринг-кода вручную (та же
   сессия), QR с `alt`-описанием.

## 7. Вопросы на архком (с рекомендациями)

1. **Конвергенция фронтендов (ADR 0006).** Принять ли вариант A как
   объявленную цель (новая IA строится в `viewer/` как единый web app;
   борд остаётся замороженным кокпитом до parity-гейта)?
   *Рекомендация: да.* Аргументация — §2.6. Freeze-механика и parity-
   чеклист ADR 0006 не меняются, меняется объявленный исход.
2. **Судьба канбана.** Канбан = вид №1 домена «Задачи» (+ переключатель
   «Список»), главный экран — «Обзор»?
   *Рекомендация: да.* Канбан доказан, но как проекция потока, не как
   Home; «Обзор» собирает внимание всех доменов (§2.3–2.4).
3. **Канон ai-brain-паттернов.** Принять breadcrumbs+back, bulk
   (select→toolbar→confirm), scroll-restore, хоткеи с input-guard как
   канон нового app?
   *Рекомендация: принять все четыре* (доказаны ежедневным использованием
   владельца); эстетику ai-brain не принимать (§3.4).
4. **Плотность/масштаб визуала.** Утвердить двухрежимную density-стратегию
   (операционный/созерцательный) + новые семантические токены
   (`--row-h-*`, `--measure-scroll`) и пользовательский тумблер
   «компакт/комфорт»?
   *Рекомендация: да* — иначе «данные» задушат «взгляд в себя» или
   наоборот; токены additive к tokens.css (правило ui-contract §8).
5. **Поэтапность без big-bang.** Утвердить волновой план §8 (оболочка →
   Память → Задачи → Агенты/Хранилища/Система → L2/мобильный) с parity-
   гейтом ADR 0006 как точкой переключения борда в read-only?
   *Рекомендация: да.* Порядок волн соответствует зависимости от
   бэкенд-готовности (ARCH-2 Ф4 раньше волны «Агенты» и т.д.).
6. **Глобальный поиск поверх двух сущностей.** Объединить поиск памяти и
   задач в одном топбар-входе с проекциями «Память | Задачи»?
   *Рекомендация: да* — merge-слой борда уже единственная санкционированная
   точка мультисерверного чтения (ADR 0007); задачи native+inbox —
   дешёвое дополнение на серверной стороне.
7. **i18n с первого дня.** Ввести словарь RU/EN (паттерн ai-brain
   `I18N`+`t()`) в новый app с волны 1?
   *Рекомендация: да*; обратный путь (инвентаризация после факта)
   — проверенная владельцем боль (ai-brain Фаза 8 не закрыта до сих пор).
8. **QR-пейринг: терминология и место.** Утвердить термины §6.1 и
   размещение `/system/devices` (домен «Система»); синхронизировать с
   `arch3-*.md` архитектора?
   *Рекомендация: да; термины данной спеки — источник истины для UI-строк.**

## 8. Поэтапный план-эскиз (без big-bang)

### Волна 0 — борд, bug-class (разрешено freeze уже сегодня)

- Обработка SSE-гэпов: `task.archived/unarchived` → `refreshBoard()`
  (известный gap ui-contract §11) — bug-class.
- a11y-фиксы борда (фокус-обводки, контраст-пары) и синхронизация
  `tokens.css` — прямо разрешены ADR 0006 (fixes-only list).
- Больше **ничего** в борд: наведение IA на замороженном борде = worst
  case (двойная работа + нарушение freeze).

### Волна 1 — оболочка нового app (`viewer/`)

Доменный sidebar + breadcrumbs + топбар с глобальным поиском и статусными
пилюлями + командная палитра + хоткеи + i18n-словарь + density-токены +
тема/настройки. «Обзор» с колодцем-героем. Существующие L1-роуты
переезжают в домен «Память» (Search → `/memory/search` и т.д.) —
редиректы со старых путей.

### Волна 2 — домен «Память»

Пульс (страница-лента), Записи (мастер-детейл + bulk + scroll-restore),
детали-scroll как роут, Теги. Всё на существующих merge-эндпоинтах
борд-сервера (`/api/memories/*` — уже long-lived asset).

### Волна 3 — домен «Задачи»

Канбан WF-1 (7 колонок, таймер validating, группы-аккордеон), Входящие +
adopt, Архив, страница задачи (Обзор/Отчёты/История), «Список»-вид.
Зависимость: WF-1 утверждён (серверная фаза) — UI-фаза сюда.

### Волна 4 — «Агенты», «Хранилища», «Система»

`/agents/execution` (assignments + панель UI-10), Специалисты-профили
(кэш борда уже есть), Харнесы; Реестр/Группы хранилищ (+mesh-слот);
Уведомления, Устройства (QR), Настройки. Зависимости: ARCH-2 Ф4 (UI-триггер
assignment), arch3 (пейринг).

### Волна 5 — L2 и мобильный проход

Кластеры-граф (`/memory/clusters`, решение по библиотеке — открытый вопрос
component-inventory §12.3), редактирование памяти, мобильная навигация
(нижние табы), PWA-обвязка при решении владельца.

### Точка переключения

Parity-гейт ADR 0006 (b): владелец подтверждает ежедневный цикл
(пульс/поиск/канбан/детали) в новом app → борд переводится в read-only и
остаётся до первой спокойной недели → снимается с ingress. Parity-чеклист
= поведение v0.3–v0.9 (владелец чеклиста — TL, по ADR 0006).

## Приложение A. Самокритика направления (для протокола архкома)

Черновой проход предлагал «Обзор» шестым доменом, единый компромиссный
размер строк и сохранение модалок для задач. Ревизия по итогам критики:

- «Обзор» — корень, не домен (иначе sidebar врёт об иерархии);
- компромиссная плотность убивает оба сценария — вместо неё контрастная
  пара режимов + тумблер (§3.3);
- задача-модалка не переживает adopt/assignment/отчёты (стек над стеком) —
  задача стала страницей (§4.1);
- anti-slop-проверка: без брендинга концепт опознаётся по «тёмная утилита
  с бирюзовым зрачком, канбаном и Lora-чтением» — это идентичность, не
  шаблон; градиенты/emoji/эйбро-капс отсутствуют; identical-card SaaS-кит
  отсутствует по построению (домены имеют разные композиции).
