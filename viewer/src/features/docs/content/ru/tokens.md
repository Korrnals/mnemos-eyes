# Токены и доступ

Токен — длинная строка-пароль, которой система узнаёт, кто стучится. У
борда несколько классов токенов с разными правами: эта страница объясняет,
какой для чего, где они живут и как не превратить удобство в дыру.

## Четыре класса токенов

| Класс | Как выглядит | Кто пользуется | На что права |
| --- | --- | --- | --- |
| Токен хранилища | `mnk_…` | борд ходит в mnemos | чтение/запись памяти; `totp_required=0` |
| ui | значение `VESMARO_UI_TOKEN` | человек в интерфейсе | все мутации доски: задачи, архив, входящие, настройки, автоматизация |
| machine | значение `VESMARO_BOARD_TOKEN` | поллер и агенты | отчёты, взятие/пульс поручений |
| device | `mnd_…` | спаренные устройства | только чтение; выдаётся пейрингом |
| enrollment | `mne_…` | удалённый исполнитель при регистрации | одна регистрация исполнителя; живёт 15 минут и сгорает ([Агенты и поручения](agents-assignments.md)) |

Токены хранилищ (`mnk_…`) борд держит при себе и никогда не отдаёт
браузеру — интерфейс видит только названия серверов и их состояние.

## Какой токен куда вводить

| Хотите | Нужен | Куда вставить |
| --- | --- | --- |
| менять задачи из браузера | ui | окно «Вход» в интерфейсе |
| запускать поллер агентов | machine | `/etc/vesmaro/poller.env` (только окружение, не конфиг) |
| подключить хранилище памяти к борду | токен хранилища | секрет `vesmaro-eyes-mnemos` при установке |
| дать доступ планшету на чтение | device | пейринг — [Подключение устройства](pairing.md) |
| подключить удалённого исполнителя без мастер-ключа | enrollment | выпускается на борде, расходуется при регистрации поллера |

## Как борд защищает токены

- Секреты хранятся только на сервере: реестр хранилищ принимает
  ссылки `env:ИМЯ_ПЕРЕМЕННОЙ` или `file:/путь` в заранее оговорённом
  каталоге секретов. Схема `plain:` (токен прямо в реестре) через API
  запрещена.
- В логах все токеноподобные строки маскируются автоматически:
  `mnk_<redacted>`, `mnd_<redacted>`, `Bearer <redacted>`.
- Класс токена определяется по префиксу и проверяется до любого действия:
  не настроен класс — операции отвечают `503` (закрыто по умолчанию);
  неверное значение — `401`.
- Токен устройства хранится в базе только хешем: увидеть исходное
  значение нельзя, можно лишь отозвать.
- Сессия входа живёт в HttpOnly-cookie: JavaScript её не читает и не
  удалит — выход делается только через сервер.

## Коды, которые встречаются при доступе

| Код | Значение | Что делать |
| --- | --- | --- |
| 401 | значение не подошло — или сессия истекла (6 часов бездействия, ротация токена) | вставьте свежий токен (возможна ротация) или войдите заново |
| 403 | токен действителен, прав нет | device-токен на мутации — так и задумано; для изменений нужен ui-токен |
| 429 | слишком часто | подождите: лимиты есть у пейринга и служебных операций |
| 503 | класс токена не настроен на борде | включите нужный класс в values и перекатите релиз |

## Что происходит при каждом запросе

Сервер проверяет токен одной цепочкой: определяет класс по префиксу,
сверяет его со списком маршрутов, разрешённых этому классу, и только
потом пропускает запрос дальше — к охране мутаций. Проверка
константновременная и стоит до любой работы с данными, поэтому «подменить
класс» текстом токена нельзя.

Честная позиция о чтениях: чтения борда открыты за ingress — токен
нужен для изменений и для идентичности в аудите, а не как барьер
чтения. Это осознанное решение для доверенной домашней сети; для доступа
извне используйте VPN.

## Вход в интерфейсе

Работа в интерфейсе после установки токен-сплита — с ui-токеном. Окно
«Вход» открывается при первой попытке что-то изменить (или по кнопке
«Войти» в верхней панели). Вставленное значение сервер проверяет сразу
(`POST /api/auth/ui-token`): успех открывает сессию — HttpOnly-cookie
`vesmaro_ui` действует на весь браузер, все вкладки; больше ничего
вставлять не нужно. Параллельно токен остаётся в текущей вкладке
(sessionStorage) — на нём работают вкладки, открытые до выката сессий.

Сессия скользящая: любой успешный авторизованный запрос продлевает её,
а 6 часов тишины дают браузеру погасить cookie самому — следующая
мутация получит `401` с текстом «сессия истекла». Кнопка «Выйти» в
верхней панели завершает сессию на сервере (`DELETE
/api/auth/ui-token`) — во всех вкладках сразу; если сервер недоступен,
вы остаётесь вошедшим, и интерфейс об этом скажет.

Попытки входа лимитированы: не больше 10 в минуту с одного адреса и 60
в минуту на весь борд, лишние отвечают `429`. Без входа борд полностью
читаем — это осознанный режим витрины, а не ошибка.

Пока окно входа открыто, нажатое действие ждёт: войдёте — выполнится
автоматически, ничего нажимать заново не нужно.

## Где взять токены

Все статичные токены — секреты кластера. Посмотреть имена и владельцев
можно так:

```bash
kubectl -n kube-agents get secrets | grep vesmaro-eyes
```

| Секрет | Ключ | Класс |
| --- | --- | --- |
| `vesmaro-eyes-ui-token` | `VESMARO_UI_TOKEN` | ui |
| `vesmaro-eyes-board-token` | `VESMARO_BOARD_TOKEN` | machine |
| `vesmaro-eyes-mnemos` | `MNEMOS_TOKEN` | токен хранилища `mnk_…` |
| `vesmaro-eyes-laptop` | `MNEMOS_LAPTOP_TOKEN` | второе хранилище, `mnk_…` |

Чарт генерирует два своих секрета сам при первой установке и сохраняет их
даже после `helm uninstall`. Как достать значение —
[Развёртывание и первый запуск](deploy.md); как сменить —
[Ротация токенов](token-rotation.md).

## Правила гигиены

- Токен не печатается в логах, issue, скриншотах и чатах. Для примеров
  используйте маски: `mnk_…`, `ui-token-…`.
- ui- и machine-токены не должны начинаться с зарезервированных
  префиксов `mnd_`, `mne_`, `mnu_`, `mnm_` — по префиксу сервер
  определяет класс.
- Одно устройство — один токен `mnd_…`; не раздавайте его между
  устройствами.
- Поллер берёт токен из окружения, никогда из конфига и никогда из
  текстов агентов.
- Подозрение на утечку — повод для немедленной ротации, процедура
  занимает минуты: [Ротация токенов](token-rotation.md).
