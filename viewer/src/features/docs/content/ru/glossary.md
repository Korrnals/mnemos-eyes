# Словарь терминов

Термины — ровно так, как их называет интерфейс. Если незнакомое слово
встретилось на доске, найдите его здесь; рядом со сложными терминами —
ссылка на страницу с подробностями.

## Термин → что это

| Термин | Что это |
| --- | --- |
| борд | vesmaro-eyes целиком: рабочий стол с задачами, агентами и автоматизацией поверх памяти mnemos |
| запись | единица памяти mnemos: текст, сырьё, теги, проект, агент, источник и статус обработки |
| хранилище | один сервер mnemos, подключённый к борду; серверов может быть несколько — например, `cluster` и `laptop` |
| группа хранилищ | объединение нескольких хранилищ в одну область пульса и поиска |
| mnemos-mesh | федерация хранилищ: транспорт, связывающий узлы-хранилища между собой; узлы видны в разделе «Узлы меша» |
| пульс | лента свежих записей из хранилищ — «Память → Пульс», область «все хранилища» |
| тег | метка записи; «Память → Теги» показывает всё, что помечено тегом, по всем хранилищам |
| статус workflow | этап жизни задачи: «открыта», «в работе», «заблокирована», «решена», «завершена», «отозвана» (колонки «бэклог» и «на валидации» — то же до взятия в работу) |
| канбан | вид «Задачи → Канбан»: колонки — этапы workflow от «бэклога» до «готово», карточки перетаскиваются мышью |
| задача | карточка на борде: название, сводка, проект, приоритет и статус workflow; задача живёт в базе борда, её память — в записях mnemos |
| archcom | значок на карточке: «требуется решение владельца»; так же подсвечивается задача, висящая «на валидации» дольше 24 часов |
| входящие | раздел «Задачи → Входящие»: записи `task:queue` из хранилищ памяти, ещё не принятые на доску |
| поручение | задача, отданная исполнителю; создаётся кнопкой «Взять в работу» на странице задачи |
| исполнитель | конкретный подключённый агент: поллер на машине, который забирает поручения из очереди и отчитывается |
| поллер | процесс-посредник на машине с агентами: раз в 10 секунд спрашивает борд «есть очередь?» и запускает агентов |
| харнес | тип среды исполнения агента: `zcode`, `copilot` |
| специалист | роль и компетенция агента: `gcw-frontend-developer` |
| токен | строка-пароль, по которой система узнаёт, кто стучится; классы различаются префиксом и правами |
| enrollment-токен | одноразовый токен `mne_…`: позволяет удалённой машине один раз зарегистрироваться исполнителем; живёт 15 минут — [Агенты и поручения](agents-assignments.md) |
| ui-токен | токен человека: значение `VESMARO_UI_TOKEN`, открывает все изменения в интерфейсе — [Токены и доступ](tokens.md) |
| machine-токен | токен машин: значение `VESMARO_BOARD_TOKEN`, им пользуются поллер и агенты для отчётов и взятия поручений |
| device-токен | токен спаренного устройства `mnd_…`: только чтение, выдаётся QR-пейрингом — [Подключение устройства](pairing.md) |
| пейринг | подключение устройства по QR-коду: устройство сканирует, владелец подтверждает, токен выдаётся однократно |
| крон | классический синтаксис расписаний планировщика; в борде его нет — расписание задаётся «ежедневно в HH:MM» или «по интервалу» |

## Откуда взялись префиксы токенов

Класс токена сервер определяет по префиксу и проверяет до любых
действий: `mnd_…` — устройство, `mne_…` — enrollment, `mnk_…` — токен
хранилища, которым борд ходит в mnemos. Поэтому ui- и machine-токены не
могут начинаться с этих сочетаний — и поэтому маскирование токенов в
логах работает автоматически.
