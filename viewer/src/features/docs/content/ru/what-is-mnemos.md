# Что такое mnemos

mnemos — движок долгосрочной памяти: он хранит записи, умеет искать по ним
и отдаёт их людям и агентам. Эта страница — понятная концепция памяти:
из чего состоит запись, как она живёт и чем связаны несколько хранилищ.
Борд vesmaro-eyes — отдельная надстройка поверх mnemos, ему посвящена
страница [Что такое vesmaro-eyes](what-is-vesmaro-eyes.md).

## Колодец, а не папка с файлами

В интерфейсе mnemos зовётся колодцем, и метафора точная: записи
складываются в общую глубину — агентами через API и MCP, скриптами,
вами. У каждой записи есть теги, проект и источник, поэтому память не
превращается в свалку: по ней можно искать, по тегам — сверлять, по
ленте «Пульс» — смотреть, что появилось свежего.

Сам mnemos — сервер без канбана и кнопок: хранение, поиск, API для
агентов и трассировки конвейера. Всё остальное — работа борда.

## Запись и её устройство

Единица памяти — запись. Откройте «Память → Записи» и любую запись —
внутри вы увидите одно и то же устройство:

| Часть записи | Что это |
| --- | --- |
| Текст | очищенное содержимое — то, что память считает сутью |
| Сырьё | исходный текст до очистки; на странице записи переключается кнопкой |
| Теги | метки, по которым запись находится вместе с соседними |
| Проект | смысловая группа — у борда проекты задач живут в той же системе |
| Агент | кто положил запись |
| Источник | откуда запись пришла |
| Уверенность | насколько движок доверяет содержимому |
| Статус и даты | где запись на конвейере обработки и когда менялась |

## Статус обработки записи

Свежая запись не сразу становится «полноценной» памятью — она проходит
конвейер. Статус обработки виден в списках и фильтре «Статус»:

| Статус | Смысл |
| --- | --- |
| сырое | запись только что легла в колодец |
| в обработке | конвейер работает над ней |
| обработано | очищено и разложено по полям |
| опубликовано | полноценная запись памяти — попадает в поиск |
| в архиве | убрана из оборота, но не удалена |

## Workflow: жизненный цикл задачи

Среди записей живут задачи — записи с рабочим жизненным циклом
(workflow). Статусы идут в строгом порядке:

| Этап | Смысл |
| --- | --- |
| бэклог | идея или заготовка, до работы |
| на валидации | проверка перед тем, как браться |
| открыто | задача принята, ждёт исполнителя |
| в работе | прямо сейчас делается |
| блокировано | упёрлось во что-то внешнее |
| решено | сделано, ждёт подтверждения |
| готово | финал |

Не всякий переход разрешён: например, из «бэклога» нельзя прыгнуть сразу
в «решено» — задачу сначала берут в работу. Борд показывает этот
жизненный цикл колонками канбана и следит за порядком переходов —
[Группы и канбан-доска](groups-kanban.md).

Задача может лежать и прямо в хранилище: записи с тегом `task:queue`
кладут туда агенты и скрипты, а борд подбирает их разделом «Входящие» —
об этом на странице [Что такое vesmaro-eyes](what-is-vesmaro-eyes.md).

## Теги

Тег — метка записи, главный способ навигации по колодцу. Раздел
«Память → Теги» — инспектор: клик по тегу показывает всё, что им
помечено, по всем подключённым хранилищам. Теги связывают и два мира
системы: у задачи на борде есть поле «Теги mnemos», поэтому карточка
находит свою память по общим меткам.

## Гибридный поиск

Поиск по памяти работает в трёх режимах — переключатель «Тип поиска» в
разделе «Память → Поиск»:

| Режим | Как ищет |
| --- | --- |
| FTS | полнотекстовый: по точным словам и их началам |
| Смысловой | по смыслу: находит записи без общих слов |
| Авто | гибрид: сервер сводит оба вида попаданий и ранжирует их вместе |

Практическое правило подсказывает сам интерфейс: колодец глубок, но
буквален — если результата нет, попробуйте меньше или другие слова.
Прыжок в поиск с любой страницы — клавиша `/`.

## Хранилища: несколько серверов памяти

Память не обязана жить на одной машине. Борд подключает несколько
серверов mnemos — например, `cluster` (основное хранилище) и `laptop`
(второе, по домашней сети). Реестр хранилищ ведёт борд: раздел
«Хранилища» на рейке слева, кнопка «+» добавляет сервер. Токены
хранилищ борд держит при себе — браузер их никогда не видит.

Хранилища просматриваются по отдельности или суммарно: область
«все хранилища» в ленте «Пульс» и в поиске, группы хранилищ — когда
нужна часть системы. Каждая запись и каждое попадание поиска помечены
сервером-источником, а если одно хранилище недоступно, интерфейс честно
пишет «недоступен» и продолжает работать с остальными.

## mnemos-mesh: федерация хранилищ

Когда хранилищ несколько и они на разных машинах, их связывает
mnemos-mesh — транспорт федерации: узлы-хранилища знают друг о друге,
обмениваются данными и отчитываются о доступности пиров. Борд видит
узлы меша как наблюдаемые сущности: в разделе «Узлы меша» на рейке —
состояние каждого узла, версия, доступность пиров и время работы.
Управление узлами — через API: интерфейс в этой версии только
наблюдает.

![Схема федерации хранилищ mnemos](diagrams/mnemos-federation.svg)

*Федерация: хранилища cluster и laptop связаны транспортом mnemos-mesh;
борд vesmaro-eyes читает оба и помечает каждую запись её
сервером-источником.*

## Где кончается mnemos

mnemos не знает ни канбана, ни поручений, ни токенов интерфейса — это
чистая память: записи, поиск, федерация. Рабочий стол поверх неё, где
записи становятся задачами, а агенты берут их в работу, — борд:
[Что такое vesmaro-eyes](what-is-vesmaro-eyes.md).
