# Автоматизация: правила и расписания

Раздел «Система → Автоматизация» отвечает на вопрос «когда и в ответ на
что запускать задачи»: по времени (расписания) или по событию на доске
(правила-хуки). Каждое правило создаёт обычное поручение — дальше работает
обычная маршрутизация исполнителей, та же, что и при ручном
«Взять в работу».

## Что умеет версия 1.13.0

В этой версии работает ручной запуск: любое правило можно выполнить
кнопкой «Запустить сейчас». Автоматический тик (расписания срабатывают
сами) появится вместе с включением движка — в 1.13.0 движок ещё не
включается, и баннер вверху раздела честно пишет «Движок не включён».
Это нормально: создавайте правила, обкатывайте их ручными запусками,
и когда движок включат — они заработают сами.

Баннер также показывает счётчики: лимит авто-запусков в день, сколько
использовано сегодня, глобальный выключатель и сколько всего расписаний
и правил. Строка «авто-запусков сегодня» дублируется в блоке «Агенты» на
«Обзоре».

## Создайте расписание

Расписание запускает задачу по времени.

1. Вкладка «Расписания» → «Новое расписание».
2. Задайте название и задачу, которую запускать; при желании —
   специалиста и харнеса.
3. Выберите триггер: «ежедневно» с временем (HH:MM) или «по интервалу» с
   минимальным шагом в одну минуту. Крон-синтаксиса нет — только эти два
   варианта.
4. Нажмите «Создать». Расписание создастся выключенным.
5. Нажмите «Включить» на карточке — включение отдельный шаг, чтобы
   ничего не заработало неожиданно.

Название должно быть уникальным: это адрес правила в журнале запусков,
и оно остаётся занятым даже после удаления. Время задавайте с запасом на
то, что борд должен быть жив: пропущенный тик не догоняется.

Пока движок выключен, «включено» означает «готово к ручным запускам и к
тику после включения движка». Если борд был выключен в момент срабатывания,
запуск не догоняется задним числом — в журнале появится «пропущено
(окно)», а компенсировать его можно ручным запуском.

## Создайте правило-хук

Правило реагирует на событие доски: событие + условия + действие.

1. Вкладка «Правила» → «Новое правило».
2. Выберите событие (поле «Событие (on)») из словаря сервера.
3. Соберите условия из закрытого словаря: поле (колонка задачи,
   приоритет, проект, статус), оператор («равно», «не равно», «один
   из») и значение. Произвольного текста нет — только то, что борд
   знает точно; у поля без закрытого набора значений условия недоступны.
4. Укажите действие — создать поручение по задаче.
5. Нажмите «Создать», затем «Включить».

Ограничение честности: перемещения карточек совершает машинный класс
токенов, поэтому событие перемещения не запускает правила в этой версии.

## Примеры, чтобы начать

| Правило | Настройки |
| --- | --- |
| Утренний прогон отчёта | расписание: задача-отчёт, «ежедневно в 09:00» |
| Раз в час проверять очередь | расписание: задача-контролёр, «по интервалу», каждые 60 минут |
| Задача заблокирована — сигнал специалисту | правило: событие изменения задачи, условие «статус = заблокирована», действие — поручение |

Начинайте с расписания на свою тестовую задачу и запускайте вручную —
это самый короткий путь понять механику.

## Запустите вручную

Кнопка «Запустить сейчас» на карточке правила выполняет его немедленно,
мимо движка и дневных лимитов. Результат — поручение в очереди задачи;
появится уведомление со ссылкой в раздел «Исполнение». Отказ запуска —
тоже событие: причина всегда видна в журнале.

Лимиты («лимит в день», «авто-запусков сегодня») относятся к будущим
автоматическим запускам движка; ручной запуск их не расходует. Отключённое
правило ручным запуском тоже не выполняется — «Запустить сейчас» доступно
у включённых правил.

## Журнал запусков

Вкладка «Журнал» — история всех запусков: «запущено», «пропущено» (с
причиной), «пропущено (окно)». Каждая строка хранит снимок правила, поэтому
журнал остаётся читаемым даже после удаления правила; ссылка в строке
ведёт к созданному поручению.

## Включайте, выключайте, удаляйте

| Действие | Что происходит |
| --- | --- |
| Включить / Выключить | персональный рубильник правила |
| Запустить сейчас | немедленный ручной запуск |
| Удалить | мягкое удаление: правило гаснет, имя остаётся занятым |

Удалённое правило нельзя воссоздать под тем же именем — это защита от
тихой подмены: старая строка сохраняется выключенной. Без ui-токена раздел
открыт только для чтения, и изменения недоступны.

## Чего в версии нет

Автоматического тика (движок), крон-синтаксиса, догоняющих запусков после
простоя, цепочек правил и внешних вебхуков. Это осознанные границы v1 —
каждое из них вернётся отдельным решением, когда дойдёт очередь.
