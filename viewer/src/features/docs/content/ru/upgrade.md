# Обновление борда

Обновление приносит исправления и новые разделы. Данные при этом не
трогаются: база живёт на PVC, а переключение версий — это замена образа
контейнера. Порядок на этой странице закрывает две реальные ловушки,
уже однажды стоившие простоя: молчаливо удержанный старый тег образа и
откат сетевого правила чужим чартом.

## Откуда берётся новая версия

Версии борда публикуются релизами репозитория: на каждый релизный тег
собирается и выкладывается образ. Источник номера версии — один:
`server/app.py`, он распространяется скриптом `scripts/sync-version.sh`
в чарт и values. Вам как оператору достаточно номера релиза из заметок
релиза.

| Где | Что | Кто меняет |
| --- | --- | --- |
| `server/app.py` | первоисточник версии | релизный PR |
| `deploy/chart/vesmaro-eyes/Chart.yaml` | версия чарта и приложения | релизный PR |
| `deploy/chart/vesmaro-eyes/values.yaml` | тег образа по умолчанию | релизный PR |
| подвал левой панели интерфейса | живая версия на борде | приходит из `/api/health` |

## Перед обновлением

1. Снимите копию — [Бэкап и восстановление](backup-restore.md). Это
   единственный шаг, который экономит день при неудаче.
2. Сверьте, что версия в репозитории и тег образа совпадают:

   ```bash
   ./scripts/sync-version.sh --check
   ```

3. Посмотрите текущую версию борда: она написана в подвале левой панели
   интерфейса, или командой:

   ```bash
   kubectl -n kube-agents get deploy vesmaro-eyes \
     -o jsonpath='{.spec.template.spec.containers[0].image}'
   ```

4. Предупредите домашних: под пересоздаётся, доска будет недоступна
   около минуты. Планируйте окно, а не обновляйтесь посреди чужой работы.

## Выполните обновление

Главное правило: каждый деплой — с явным тегом образа. Helm помнит
значения прошлых команд и молча держит старый тег, если новый не указать
явно: под перезапустится, но останется на прежней версии — формальное
обновление без обновления.

```bash
helm upgrade --install vesmaro-eyes deploy/chart/vesmaro-eyes \
  -n kube-agents --atomic --timeout 5m \
  -f my-values.yaml \
  --set image.tag=<новая версия>

kubectl -n kube-agents rollout status deployment/vesmaro-eyes --timeout=300s
```

Затем — обязательная проверка фактического образа пода (должен совпасть
с тегом из команды):

```bash
kubectl -n kube-agents get deploy vesmaro-eyes \
  -o jsonpath='{.spec.template.spec.containers[0].image}'
```

Флаг `--atomic` при неудаче откатывает релиз сам; без него откат — вручную
(ниже).

## Проверьте после обновления

- В подвале левой панели интерфейса — новая версия.
- `/api/health` отвечает `ok:true` и видит все хранилища.
- Живой прогон: откройте доску, перетащите карточку, загляните в раздел
  «Агенты → Исполнение» и «Система → Автоматизация».
- Поллер на машине агентов не требует обновления при обычном релизе —
  достаточно, что он продолжает отвечать.

## Откат

Откат возвращает прежнюю версию релиза — данные остаются как есть:

```bash
helm history vesmaro-eyes -n kube-agents      # найти предыдущую ревизию
helm rollback vesmaro-eyes <ревизия> -n kube-agents
kubectl -n kube-agents rollout status deployment/vesmaro-eyes
```

После отката — та же проверка образа пода: ревизия должна показывать
прошлый тег. Старый интерфейс `/board` на время сомнений остаётся
запасным входом для сверки — если он включён в вашей установке.

## Особые случаи

- **Обновили чужой чарт сетевых политик** (`agentsnode-policies`) — его
  upgrade тихо откатывает правило для traefik, и борд отвечает `502`.
  Пере-примените патч: `deploy/netpol-traefik-fix.md` в репозитории.
- **Обновлялся k3s/traefik** — проверьте, что у traefik-сервиса остался
  `externalTrafficPolicy: Local` (иначе пейринг видит служебный IP вместо
  реального адреса устройства).
- **Новый сервер памяти с другим адресом** — добавьте его в egress-список
  чарта (`networkPolicy.egress` в values) и сделайте
  `helm upgrade`, иначе хранилище не заработает: осознанный компромисс
  изоляции.
- **Смена корневого приложения** (`rootApp`) — тот же образ, только env:
  обновление значения пересоздаёт под с тем же окном простоя в минуту.
