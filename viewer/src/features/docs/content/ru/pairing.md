# Подключение устройства

Пейринг — способ дать телефону или планшету доступ к борду без ручного
вбивания токенов: устройство сканирует QR-код, а владелец на доверенном
компьютере подтверждает подключение. Устройство получает собственный
токен `mnd_…` с правами только на чтение.

## Как это устроено

Схема — прямая, без облака: устройство и борд в одной домашней сети,
никакой третьей стороны в трафике нет. Подключение требует двух действий
владельца: создать запрос и подтвердить его. Автопринятия не существует.

Правила безопасности, зашитые в протокол:

- Код пейринга живёт 3 минуты и сгорает после первого использования.
- Токен выдаётся ровно один раз и только с того IP, с которого
  устройство впервые постучалось.
- Токен `mnd_…` — только чтение: задачи, память, события, здоровье.
  Мутации с устройства отвечают отказом.
- Активных устройств не больше пяти; шестое подключение потребует
  сначала отозвать одно из старых.

## Экран пейринга

Серверная часть пейринга работает с версии 1.12.0, экран в интерфейсе —
с 1.17.0. Всё подключение делается из браузера, без команд и без API.

Владельцу: раздел «Система → Устройства». Кнопка «Подключить устройство»
открывает диалог: QR-код для сканирования и, если камеры нет, «Код
подключения» — его вводят вручную на устройстве. Под кодом тикает
обратный отсчёт: код живёт 3 минуты. Когда устройство постучится, в
диалоге появится «Запрос подключения» — имя и IP устройства, четыре
цифры «Кода подтверждения». Сверьте цифры с экраном устройства и
нажмите «Подтвердить» (или «Отклонить» — тогда устройство токен не
получит). Без входа владельца список устройств и подключение недоступны.

На устройстве: страница `/pair` — «Подключение устройства». Введите
«Код подключения» с экрана владельца и имя устройства, покажите
владельцу свои четыре цифры и ждите. Страница сама проверит статус один
раз через минуту; есть и кнопка «Проверить». После подтверждения —
«Устройство подключено» и «Токен устройства»: он показывается один раз,
устройство хранит его у себя.

## Предусловия

- Настроен ui-токен (`VESMARO_UI_TOKEN`): без него весь пейринг отвечают
  `503` — защита «закрыто по умолчанию». См. [Токены и
  доступ](tokens.md).
- Для списка устройств и подтверждения нужна сессия владельца —
  [Первый вход для члена семьи](first-login.md).
- Устройство открывает борд по HTTPS с доверенным сертификатом. Для
  lab-домена с самоподписанным сертификатом на устройство ставится
  собственный CA — ритуал установки и сверка отпечатка SHA-256 описаны в
  `deploy/chart/vesmaro-eyes/RUNBOOK.md` репозитория.

## Через API: тот же протокол для скриптов

Экран повторяет шаги протокола один в один; те же действия доступны
командами к API — пригодится для автоматизации. Команды выполняются с
доверенного компьютера. Ниже `ui-token-…` — маска вашего ui-токена,
`board.example.com` — адрес борда.

![Схема QR-пейринга](diagrams/pairing-flow.svg)

*Четыре шага пейринга: владелец создаёт запрос, устройство предъявляет
код, владелец сверяет четыре цифры и подтверждает — устройство
получает токен однократно.*

1. Создайте запрос пейринга:

   ```bash
   curl -sk -X POST https://board.example.com/api/pairing \
     -H "Authorization: Bearer ui-token-…" \
     -H "Content-Type: application/json" \
     -d '{"device_name":"планшет на кухне"}'
   ```

   Ответ: `pairing_id`, одноразовый `code`, четырёхзначный `verify` для
   сверки экранов и `expires_at` (3 минуты).

2. Устройство предъявляет код — сегодня так делает клиентская
   интеграция: POST `/api/pairing/exchange` с телом `{"code":"…",
   "device_name":"…"}`. Пока вы не подтвердили, оно получает статус
   «awaiting_confirmation» и тот же `verify`.

3. Сверьте четыре цифры `verify` на обоих экранах и подтвердите:

   ```bash
   curl -sk -X POST \
     https://board.example.com/api/pairing/pairing-id-…/confirm \
     -H "Authorization: Bearer ui-token-…" \
     -H "Content-Type: application/json" \
     -d '{"allow":true}'
   ```

4. Устройство повторяет exchange — и получает единственный ответ с
   `device_token` (`mnd_…`), который хранит у себя. Повторная выдача
   невозможна: код сгорел.

`verify` — это защита от перепутанных серверов и опечаток, а не
криптография: настоящую защиту держат короткий TTL, одноразовость и
привязка к IP.

## Управляйте устройствами

Список живёт там же: «Система → Устройства». У каждой записи — статус
(«активно», «истекло», «отозвано»), дата подключения, «последний IP» и
два срока: «скользящий TTL до» и «жёсткий до». Отзыв — кнопка
«Отозвать» с предупреждением «Отзыв необратим — устройству понадобится
новый пейринг».

Тот же список и отзыв доступны через API:

```bash
# список подключённых устройств (без токенов)
curl -sk https://board.example.com/api/devices \
  -H "Authorization: Bearer ui-token-…"

# отзыв устройства (необратим — только новый пейринг)
curl -sk -X DELETE https://board.example.com/api/devices/device-id-… \
  -H "Authorization: Bearer ui-token-…"
```

Токен устройства живёт, пока им пользуются: 30 дней скользящего срока,
жёсткий потолок — 90 дней. Отзыв мгновенный и окончательный.

## Если что-то пошло не так

- Код истёк (3 минуты) или уже использован — диалог напишет «Пейринг
  истёк — начните заново»; на экране API это `410`. Создайте новый
  пейринг.
- `403` при обмене — устройство стучится с другого IP, чем в первый раз
  (например, сменилась сеть). Создайте новый пейринг.
- `409` на шестом устройстве — отзовите одно из старых.
- `503` — на борде не настроен ui-токен.

Смена скомпрометированного токена — [Ротация токенов](token-rotation.md).
