# Агенты и поручения

Борд не просто хранит задачи — он умеет отдавать их автоматическим
исполнителям и показывать, что те делают прямо сейчас. В разделе «Агенты»
два экрана: «Исполнение» отвечает на три вопроса — кто подключён, что
делает сейчас и что застряло в очереди; «Подключение» — реестр
исполнителей: одобрение, включение, отзыв и выпуск токенов для
удалённых машин.

## Четыре слова, чтобы говорить на одном языке

| Слово | Что это | Пример |
| --- | --- | --- |
| Харнес | тип среды исполнения агента | `zcode`, `copilot` |
| Специалист | роль, компетенция агента | `gcw-frontend-developer` |
| Исполнитель | конкретный подключённый агент: харнес + машина | поллер на ноутбуке |
| Поручение | задача, отданная исполнителю | «взять T-12 в работу» |

## Раздел «Исполнение»

Откройте «Агенты → Исполнение». Сверху — полоса исполнителей: по чипу на
каждого. Точка на чипе — присутствие:

| Точка | Значение |
| --- | --- |
| зелёная «онлайн» | пульс не старше 2 минут |
| янтарная «пульс пропущен» | молчит 2–10 минут |
| полая «не на связи» | тишина больше 10 минут |

Под полосой — список поручений тремя группами: «активные» (взяты и
исполняются), «очередь», «терминальные за сегодня» (свёрнуты; если за
сегодня завершённых нет, но история есть — над группой появится подпись
«Последние завершённые» с датой). Строка поручения: состояние, задача,
специалист, исполнитель и честный возраст — «взято 4 мин назад», «пульс
1 мин назад».

Клик по строке открывает карточку поручения: таймлайн фаз (создано →
взято → старт → пульсы → финиш), строка идентичности и финальный отчёт.
Подпись «от … · не проверено» означает: исполнитель сам заявил, кто он, —
сервер пока это не подтвердил. Внизу раздела — «Лента исполнения»: общий
поток событий по всем поручениям. Пустые состояния здесь деятельные:
«Поручений нет» предлагает ссылку «Открыть задачи».

## Раздел «Подключение»

«Агенты → Подключение» — реестр исполнителей. Наверху кнопка «Добавить
исполнителя» (про неё — ниже), под ней три полосы: «Ожидают
подтверждения», «Подключённые», «Отозванные»; пустые полосы не
показываются. Строка исполнителя: точка присутствия, имя и харнес,
транспорт, версия, хост, возраст последней связи; заявленные
«Возможности» — чипами.

Доверие к новичку не слепое: в строке стоит честный чип «не проверено»
— имя, хост и версия заявлены самим исполнителем, и сервер подтвердить
это не может. У ожидающих подтверждения видна и строка происхождения:
«enrollment-токен» (пришёл по приглашению с удалённой машины) или
«машина-токен» (зарегистрировался сам с мастер-ключом).

Подключение новичка — два шага, оба в реестре:

1. «Одобрить» — кнопка стоит прямо в строке ожидающего: сервер
   подтвердил, что этого исполнителя ждём.
2. «Включить» — маршрутизация берёт только включённых; одобрение само
   по себе исполнителя в маршрут не добавляет. Подсказка у кнопки
   говорит об этом же.

Остальное управление — в контекстном меню: правый клик по строке
реестра или по чипу исполнителя в полосе на «Исполнении» (у чипа есть и
кнопка «⋯», проступающая при наведении). Пункты по состоянию:
«Включить»/«Отключить», «Отозвать», «Копировать id», «Удалить»; у
ожидающего — «Одобрить»; у чипа на «Исполнении» — ещё и «Открыть
реестр».

Два действия необратимы и оба под подтверждением:

- «Отозвать» — доверие не восстанавливается: состояние терминальное,
  исполнитель должен зарегистрироваться заново (новая запись и новый
  секрет).
- «Удалить» — запись исчезает из реестра жёстко: секрет умирает вместе
  с ней, имя освобождается; ссылки в активных поручениях сохраняются.

«Отключить» — мягкая мера: маршрутизация временно не берёт исполнителя,
строка помечена «отключён владельцем (маршрутизация выключена)»,
«Включить» возвращает всё как было.

## Дайте задачу агенту

Поручение создаётся только на странице задачи:

1. Откройте задачу и вкладку «Исполнение».
2. Нажмите «Взять в работу».
3. В форме выберите специалиста и харнеса. Исполнитель — «По умолчанию»
   или конкретный: офлайн-исполнители видны, но недоступны для выбора.
4. Посмотрите «Превью маршрута»: кому поручение уйдёт по текущим
   правилам. Превью — прогноз; факт покажет, кто реально взял.
5. Нажмите «Назначить». Поручение встанет в очередь — статус «в очереди».

Если доступного исполнителя нет, кнопка всё равно активна: поручение
честно подождёт в очереди с пометкой «ждёт исполнителя».

## Состояния поручения

| Состояние | Что происходит |
| --- | --- |
| в очереди | ждёт, пока поллер заберёт |
| взято | исполнитель забрал, ещё не начал |
| исполняется | работает, пульс каждые 60 секунд |
| завершено | финальный отчёт готов |
| провал | исполнитель сообщил об ошибке — причина в отчёте |
| отменено | отменил владелец |
| истекло | нет старта или пульса — сработал «жнец» сервера |

Действия владельца: «Отменить» (с предупреждением «исполнителю будет
отправлен сигнал остановки») и «Перезапустить» для проваленных и
истёкших — форма откроется предзаполненной.

Присутствие исполнителя и жизнь поручения — независимые факты, и доска
показывает оба, никогда не схлопывая: чип «исполнитель не на связи
12 мин» может соседствовать со строкой «исполняется, пульс 12 мин назад,
истечёт через ~18 мин». Зелёный цвет — только по свежему факту, янтарный —
только по реальному пропуску.

## Кому поручается по умолчанию

«Система → Настройки», блок «Исполнение»: задайте «Исполнителя по
умолчанию» и «Запасного». Правила маршрута видны в превью и в строке
поручения: «целевой исполнитель», «по специалисту», «по специалистам
задачи», «по умолчанию». Дефолт обязан быть строго онлайн — пропустившему
пульс исполнителю поручение по умолчанию не уйдёт.

## Подключите исполнителя

Исполнитель — это поллер: небольшой процесс на машине с агентами, который
раз в 10 секунд спрашивает борд «есть очередь?» и запускает локальные
процессы по строгому списку разрешённых команд. Сводка установки:

1. Python 3.10+ и зависимости: `pip install --user httpx pyyaml`.
2. Конфиг `~/.config/mnemos-eyes/poller.yaml` (права 0600): адрес борда,
   имя исполнителя, allowlist команд, сертификат lab-CA.
3. Машинный токен — только через окружение, например
   `/etc/vesmaro/poller.env` со строкой `VESMARO_BOARD_TOKEN=…` (где взять
   значение — [Токены и доступ](tokens.md)).
4. Сервис: systemd-юнит `vesmaro-assignment-poller` (для ноутбука с
   distrobox — user-юнит). Подробности — `deploy/poller/README.md` в
   репозитории.

Проверка без запуска: `python3 scripts/assignment_poller.py --once` —
сухой прогон одного цикла, без взятия поручений.

После первого подключения исполнитель появляется на странице
«Агенты → Подключение» в полосе «Ожидают подтверждения» с пометкой
«ожидает подтверждения владельца». Дальше из интерфейса: «Одобрить»,
затем «Включить» — маршрут берёт только включённых (механика — в
разделе «Подключение» выше). Тот же результат даёт API
(`PATCH /api/executors/{id}`, ui-токеном) — как альтернатива для
скриптов.

### Удалённая машина: enrollment-токен вместо мастер-ключа

Машинный токен борда — мастер-ключ: на своей машине он уместен, на
арендованном VPS — нет. Для удалённых исполнителей выпускайте
одноразовый enrollment-токен: он позволяет машине один раз
зарегистрироваться исполнителем и больше ни на что не годится. Токен
выпускается прямо в интерфейсе: на странице «Агенты → Подключение»
нажмите «Добавить исполнителя».

1. Заполните форму: «Название (для себя)» (например, «vps-1»), «Харнес
   (подсказка для команд)» и при желании «Имя исполнителя» — затем
   «Создать токен».
2. На экране токена значение `mne_…` скрыто: нажмите «Показать» и
   «Копировать». Токен живёт 15 минут — рядом тикает обратный отсчёт —
   и сгорает после первого использования. Живых токенов одновременно не
   больше трёх.
3. Ниже — блок «На VPS выполните»: четыре команды от регистрации до
   запуска поллера, ваш токен уже внутри. «Скопировать всё» переносит
   блок целиком; выполните команды на удалённой машине. Секрет
   исполнителя из ответа показывается один раз — он идёт в env-файл
   поллера вместо мастер-ключа.
4. После регистрации исполнитель появится в полосе «Ожидают
   подтверждения», а строка токена — «использован», с именем
   исполнителя и IP, с которого он пришёл. Сверьте происхождение с
   ожидаемой машиной, затем «Одобрить» → «Включить».

Постоянный статус-экран токенов — панель «Токены подключения» под
реестром (подпись «живые + история»): обратные отсчёты живых токенов,
статусы «ждёт подключения», «использован», «истёк», «отозван» и отзыв
невостребованного кнопкой «Отозвать» с подтверждением. Без входа панель
честно подсказывает: создание и статусы требуют ui-токен.

Тот же выпуск остаётся доступен через API — `POST
/api/executors/enrollment` (создание), `GET`/`DELETE
/api/executors/enrollment` (список живых и отзыв) — как альтернатива
для скриптов. Классы токенов и маскирование `mne_…` —
[Токены и доступ](tokens.md).

Исполнители бывают с транспортом «local» и «mesh» — транспорт виден на
чипе в полосе исполнителей. Mesh-исполнители пока наблюдаемые: назначать
им поручения (в том числе по умолчанию) система в этой версии не умеет.

Автоматически запускать задачи по расписанию или по событию —
[Автоматизация: правила и расписания](automation-rules.md).
