# Устранение неполадок

Симптомы собраны по частоте и тяжести: сначала то, что мешает открыть
борд, потом то, что мешает работать. Для каждого — причина и короткий
путь к лечению. Если симптома нет в списке, назовите версию из подвала
левой панели — с ней ищут дальше.

## Быстрая диагностика за минуту

Три проверки отвечают на большинство вопросов «что вообще происходит»:

```bash
# 1. жив ли борд и видит ли хранилища (ok:true + блок серверов)
curl -ksS https://board.example.com/api/health | head -c 400

# 2. отвечает ли корень (ожидаем HTML, не 502/503)
curl -ksS -o /dev/null -w '%{http_code}\n' https://board.example.com/

# 3. принимает ли сервер мутации без токена (ожидаем 4xx/503, не 5xx)
curl -sS -o /dev/null -w '%{http_code}\n' \
  -X POST https://board.example.com/api/tasks \
  -H 'Content-Type: application/json' -d '{"title":"diag"}'
```

Параллельно гляньте на «Обзоре» блок «Хранилища»: «работает» /
«недоступно» / «отключено» — это уже половина диагноза.

## Борд не открывается

**Ingress отвечает `502`.** Сетевая политика не пускает traefik до пода —
обычно после обновления чужого чарта `agentsnode-policies`, который
откатил правило. Пере-примените патч из `deploy/netpol-traefik-fix.md`:

```bash
kubectl -n kube-agents get networkpolicy agentsnode-policies -o yaml \
  > /tmp/netpol-backup-$(date +%Y%m%d-%H%M).yaml
kubectl patch networkpolicy agentsnode-policies -n kube-agents \
  --type=json --patch-file deploy/k8s/netpol-traefik-fix-patch.yaml
```

**Бесконечное «Загружаем…»** — API поднят, а хранилища молчат: откройте
`/api/health` и смотрите блок серверов. Красная точка «недоступен» на
«Обзоре» — то же самое, но по-человечески.

**Предупреждение сертификата** для lab-домена — норма, «Дополнительно →
Перейти на сайт». Если предупреждение сменилось ошибкой соединения —
проверьте срок сертификата: `./scripts/gen-tls-secret.sh --check`
(продление — [Ротация токенов](token-rotation.md)).

## Вход не принимается

| Симптом | Причина и лечение |
| --- | --- |
| «Сервер не принял токен — проверьте значение и попробуйте ещё раз» | вход не прошёл проверку у порога: значение устарело или это токен другого класса. Под строкой ошибки сервер поясняет, какой класс пришёл и какой нужен (например, вставлен машинный токен там, где нужен ui-токен). Возьмите свежее значение из секрета `vesmaro-eyes-ui-token` и вставьте заново |
| «Сессия истекла — войдите ещё раз» | сессия закрылась: 6 часов бездействия либо ротация ui-токена на сервере. Войдите заново — новая сессия снова накроет все вкладки браузера |
| Мутации отвечают `503` | класс токена не настроен на борде — включите `uiToken.enabled` ([Токены и доступ](tokens.md)) |
| Вход отвечает `429` | сработал лимит попыток: не больше 10 в минуту с одного адреса. Подождите минуту и попробуйте снова |
| После входа всё снова просит токен | сессия живёт в cookie; проверьте, что браузер не блокирует cookies для адреса борда |
| Действие «висит», пока открыто окно входа | так задумано: войдите — действие выполнится само |

## Хранилище памяти «недоступен»

1. Откройте `https://board.example.com/api/health` — блок упавшего
   сервера покажет причину.
2. Проверьте адрес в списке разрешённых (`memoryHostsAllowlist` в
   values): без хоста в списке борд отказывается даже пробовать —
   [Развёртывание и первый запуск](deploy.md).
3. Проверьте сам mnemos и сетевую политику кластера: борду разрешён
   выход только к перечисленным адресам.
4. Если ноутбучное хранилище периодически уходит в офлайн, пробы
   `/api/health` становятся медленными. Почините связь или временно
   отключите сервер в реестре (через API хранилищ).

## Разделы «Задачи», «Агенты», «Автоматизация» недоступны

Борд умеет работать в двух режимах: против борда (все домены на месте) и
напрямую против mnemos (только «Память»). Если при открытии домена видно
«Раздел недоступен в режиме mnemos» — источник данных указан неверно:
проверьте `mnemos.cluster.url` в values, он должен указывать на
board-совместимый сервис.

## Задачи

- **Задача пропала с доски** — загляните в «Задачи → Архив» и найдите
  поиском. Вернёт кнопка «Вернуть на доску».
- **«Недопустимый переход: сначала в работу»** — колонки меняются по
  рабочему процессу; задачу из бэклога нельзя прыгнуть в «решено»
  ([Группы и канбан-доска](groups-kanban.md)).
- **Задача не редактируется (423)** — ей больше 24 часов, контент
  защищён. Диалог предложит «Изменить принудительно» с пометкой в
  истории.
- **Карточка вернулась на место после перетаскивания** — перемещение
  не прошло (например, конфликт или разрыв связи). Попробуйте снова;
  при повторении смотрите `/api/health`.
- **Запись пропала из «Входящих»** — она исчезла из источника
  (`task:queue` в хранилище), и примять её уже невозможно: источник
  честнее кэша. Сканируйте снова — появятся новые записи.

## Поручения и агенты

- **Поручение висит «в очереди»** — поллер не забирает. Проверьте на
  машине агентов: сервис запущен (`systemctl status
  vesmaro-assignment-poller`), токен в `/etc/vesmaro/poller.env`
  актуален, allowlist конфига содержит нужную команду. Сухой прогон:
  `python3 scripts/assignment_poller.py --once`.
- **«Ждёт исполнителя (офлайн)»** — целевой исполнитель не на связи;
  выберите другого или дождитесь его.
- **«Пульс пропущен»** у исполнителя — процесс жив, но молчит 2–10 минут:
  смотрите `journalctl` поллера.
- **Поручение «истекло»** — не было старта или пульса в срок; нажмите
  «Перезапустить» ([Агенты и поручения](agents-assignments.md)).

## Автоматизация и пейринг

- **«Движок не включён»** — норма для 1.13.0: расписания не тикают сами,
  работает «Запустить сейчас» ([Автоматизация: правила и
  расписания](automation-rules.md)).
- **Запуск «пропущен»** — причина всегда в журнале, вкладка «Журнал».
- **Пейринг отвечает `503`** — на борде не настроен ui-токен;
  `409` — заняты все пять слотов устройств ([Подключение
  устройства](pairing.md)).

## Мелкое, но частое

- **«Данные на HH:MM»** — надпись появляется, если поток живых обновлений
  временно рвался. После восстановления соединения доска обновится сама;
  надёжнее — обновить страницу.
- **Плашка «Вышло обновление приложения»** в углу экрана — вышел новый
  деплой, а открытая вкладка всё ещё работает на старой сборке. Нажмите
  «Обновить» в плашке — страница перезагрузится на актуальную версию.
  Сама вкладка никогда не перезагружается без вас: плашка проверяет
  сервер при возврате на вкладку и раз в пять минут и просто напоминает.
- **Версия в панели не изменилась после обновления** — helm переиспользовал
  старый тег образа; повторите upgrade с явным
  `--set image.tag=…` ([Обновление борда](upgrade.md)).
- **Правило нельзя создать под старым именем** — удаление мягкое, имя
  остаётся занятым; возьмите новое.
