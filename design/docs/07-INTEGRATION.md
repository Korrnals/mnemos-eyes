## 0. Принцип

Strangler, а не Big Bang: токен-слой эволюционирует первым (имена
заморожены — только добавление нейро-слоя и эволюция значений), затем
оболочка, затем компоненты, затем экраны. Каждый фазовый PR самодостаточно
зелёный: vitest (включая wcag.test), typecheck, бюджеты чанков, паритет
ru/en словарей, паритет токенов `viewer/` ↔ `web/` (ADR 0006).

## 2. Последовательность и параллелизм

И0 → И1 → И2 последовательно (токены — вход для всего). После И2 параллельно
возможны И3 и И4 (разные фичевые зоны, разные сессии/worktree). И5 — после
И4 (переиспользует сетки списков). Демо-стенд живёт в ветке и служит
эталоном до полного переноса; после И5 стенд архивируется (README-пометка).

## 3. Риски и контрмеры

- **Замороженные имена токенов** — расширяем нейро-слоем, не переименовываем; паритетная правка в двух местах (viewer + web) одним PR.
- **Snapshot-волна** — И1 красит десятки snapshot-тестов Shell; обновление снапшотов допустимо только в И1-PR с пояснением в описании.
- **Бюджеты** — canvas-виджет без зависимостей; следить за пулом entry ( budgets CI-гейта); woff2 — только уже используемые семейства.
- **i18n** — все новые строки в ru.ts и en.ts в одном PR (компиляторная парity-проверка не пропустит дрейф).
- **Прод-приёмка владельца** — перед выкаткой каждой фазы в прод: скриншот-стенд + journey-проход владельцем (продуктовая планка 2026-09-23); без этого фаза не сливается.
